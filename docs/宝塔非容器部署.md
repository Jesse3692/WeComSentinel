# 宝塔非容器部署

方案：Linux 宝塔 Nginx + Python 3.12 虚拟环境 + systemd。前端构建后放在 `frontend/dist`，由 Python 同源提供；SQLite 与头像位于项目 `data/`，无需 Docker 或 MySQL。只运行一个实例、一个 worker。

本方案使用当前项目的 `pyproject.toml`、`uv.lock` 安装 Python 依赖。已提供配置并进行本地检查，尚未在 Linux 宝塔服务器验收。

## 1. 上传项目和准备环境

以下命令在服务器 root 的 Bash 终端执行，假设目录为 `/www/projects/wecom-monitor`。如果你现有目录为 `/www/projects/test` 等，可以继续使用，但需要同时修改服务文件的 `WorkingDirectory`、`ExecStartPre` 和 `ExecStart` 三处路径。

将源码上传到该目录，排除本地 `.env`、`.venv`、`node_modules`、`data`、`backups` 和 `.git`。源码放在公开网站目录之外。保留服务器已有的正式配置和数据，不要用本地演示库覆盖。

在宝塔或系统中安装 Python 3.12；命令必须指向服务器实际的 Python 3.12，不替换系统 Python。先检查：

```bash
cd /www/projects/wecom-monitor
python3.12 --version
id www
systemctl --version
```

若宝塔的 Python 没有加入 PATH，用其绝对路径替换下文的 `python3.12`。模板以宝塔常用的 `www:www` 运行；若服务器没有该用户，应先准备服务用户并同步修改服务文件和下面的权限命令。

安装 uv 和项目依赖：

```bash
python3.12 -m pip install 'uv==0.13.4'
python3.12 -m uv sync --locked --no-dev --python "$(command -v python3.12)" --no-managed-python --no-python-downloads
.venv/bin/python --version
```

`--locked` 防止安装过程修改锁文件，`--no-dev` 不安装测试工具；指定现有解释器并关闭自动下载，避免再访问 Python 二进制下载源。首次安装依然需要访问 Python 包源。不要使用旧的 `requirements.txt` 或 `requirements.lock`，当前依赖已迁移到 uv。

**若原来 Docker 应用已经成功运行过并存有正式数据，应先通过原应用的在线备份导出数据库和媒体，再停止旧服务，将数据恢复到本方案的 `data/` 并保留原 `PAYLOAD_KEY`。Docker 数据卷不会自动出现在这个目录中。** 如果此前仅卡在镜像下载，则按全新安装即可。

## 2. 准备前端

可以在本地构建，直接把 `frontend/dist/` 上传到服务器相同位置。这种方式服务器无需安装 Node.js。使用本地已配置的 Node.js 24 和 pnpm 11.25.0，在项目根目录执行：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

如果选择服务器构建，在宝塔安装 Node.js 24 并确保当前终端可用，然后执行：

```bash
node --version
npm install -g pnpm@11.25.0
cd /www/projects/wecom-monitor/frontend
pnpm install --frozen-lockfile
pnpm run build
cd ..
```

最终确认服务器存在 `frontend/dist/index.html` 和 `frontend/dist/assets/`。不要用 `pnpm dev` 作为生产服务。

## 3. 配置正式环境

```bash
cd /www/projects/wecom-monitor
# 仅首次复制，不覆盖已有 .env。
cp -n deploy/baota-native.env.example .env
.venv/bin/python -m app.cli generate-keys
```

通过宝塔文件编辑器编辑 `.env`，填入生成的 `SECRET_KEY`、`PAYLOAD_KEY`，设置真实的 HTTPS `PUBLIC_ORIGIN`（不加末尾 `/`），以及钉钉和企微凭据。保持生产环境、Secure Cookie、关闭演示登录。密钥只在首次全新部署时生成；迁移已有数据或更新项目时保留原密钥。

若沿用此前 Docker 版本的 `.env`，必须将容器路径改为：

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./data/monitor.db
MEDIA_DIR=./data/media
```

准备写入目录和读取权限：

```bash
mkdir -p data/media backups
chown -R www:www data backups
chown root:www .env
chmod 640 .env
chmod 750 data backups
```

`www` 必须能够遍历项目父目录并读取源码、虚拟环境与前端构建文件。不要给整个项目 `777` 权限；安装依赖和修改源码仍由部署账号负责。

## 4. 安装开机启动服务

确认 `deploy/wecom-monitor.service` 中路径、用户和组与实际一致：

```bash
cp deploy/wecom-monitor.service /etc/systemd/system/wecom-monitor.service
systemd-analyze verify /etc/systemd/system/wecom-monitor.service
systemctl daemon-reload
systemctl enable --now wecom-monitor
systemctl status wecom-monitor --no-pager
journalctl -u wecom-monitor -n 100 --no-pager
curl --fail http://127.0.0.1:8000/readyz
```

启动前自动执行数据库迁移；应用在本机 8000 端口监听，由 systemd 管理退出重启与开机启动。正常就绪响应为 `{"status":"ready"}`。迁移或配置错误先查看日志。不要同时用宝塔 Python 项目管理器、Supervisor、手工 Uvicorn 再启动同一个应用。

首次创建管理员，用真实钉钉企业 ID 和企业内 userid（不是手机号）：

```bash
cd /www/projects/wecom-monitor
runuser -u www -- .venv/bin/python -m app.cli create-admin \
  --corp-id '真实钉钉企业ID' --user-id '真实钉钉userid' --name '管理员'
```

## 5. 宝塔反向代理和平台接入

域名解析到服务器，安全组与防火墙放行 80、443。宝塔新建纯静态网站，站点目录使用单独空目录，申请 SSL 证书并强制 HTTPS。

在站点添加反向代理，目录 `/`，目标 `http://127.0.0.1:8000`，发送域名 `$host`，关闭缓存。也可手动使用 [Nginx 片段](../deploy/baota.nginx.conf)，两种方式二选一。整个站点都应代理，包括 `/api/`、`/callbacks/` 和 `/assets/`。如果宝塔默认静态文件正则规则导致 JS、CSS、图片 404，去掉该站点相应匹配规则，使资源也经过应用代理；保留证书验证配置。

检查配置并重载 Nginx，访问 `https://你的域名/readyz` 和首页。8000 不需要公网开放；正式环境 `/docs` 不可用是预期行为。

将钉钉 H5 首页设为 `https://你的域名/`，配置安全域名、可见范围与权限，从钉钉工作台登录。管理页新增企微主体，凭据引用使用 `.env` 中的 `ACME`，复制生成的回调 URL 到企微后台，配置同一组 Token 和 AESKey，以及平台要求的可信出口 IP。详见 [配置指南](配置指南.md)。

创建主体后，可按实际主体 ID 初始化快照：

```bash
runuser -u www -- .venv/bin/python -m app.cli sync-profiles --tenant-id 1
```

快照不是历史事件导入。项目仍需完成真实钉钉登录、企微回调与业务事件联调。

## 6. 备份、更新和排查

每次更新前，从项目目录执行在线备份，并另行安全保存 `.env` 和原密钥：

```bash
cd /www/projects/wecom-monitor
runuser -u www -- .venv/bin/python -m app.cli backup \
  --output "backups/manual-$(date +%Y%m%d-%H%M%S)"
```

确认备份成功并转存到独立存储。备份包含数据库与媒体，不直接复制正在写入的 SQLite 文件。

更新时先 `systemctl stop wecom-monitor`，上传新代码和前端构建产物，保留 `.env`、`data/`、`backups/`、服务器 `.venv`，在项目根目录重新执行前述 `uv sync --locked --no-dev ...` 命令，然后：

```bash
systemctl start wecom-monitor
curl --fail http://127.0.0.1:8000/readyz
```

修改 `.env` 后执行 `systemctl restart wecom-monitor` 即可；修改 service 后先 `systemctl daemon-reload`。不要在运行中同步依赖。

- 502：检查 `systemctl status`、`journalctl` 和本机 `/readyz`，确认端口未被其他进程占用。
- 数据库只读：检查 `data/`、数据库、WAL/SHM、媒体的属主，均应允许服务用户写入。
- 依赖无法导入或解释器无权限：检查 service 指向服务器 `.venv/bin/python`，以及其真实解释器的访问权限；不要使用位于 root 私有目录下的解释器。
- 页面能打开但无法登录：正式环境使用钉钉工作台登录，核对应用配置和管理员 userid，不能使用演示账号。

恢复时停止服务，恢复原数据库、媒体和原密钥，处理旧 WAL/SHM 文件并修复文件属主，再启动执行迁移。数据库迁移后回退代码前确认兼容性。

参考：[uv 锁文件与同步](https://docs.astral.sh/uv/concepts/projects/sync/)、[systemd 服务配置](https://www.freedesktop.org/software/systemd/man/systemd.service.html)。
