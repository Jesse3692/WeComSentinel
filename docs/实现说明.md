代码核对日期：2026-10-24，源码基线 `24e6586`。本文描述当前行为；[第 1 天技术方案](第1天技术方案.md) 中的排期、细分表设计和增强能力保留为历史评审内容。操作入口见 [README](../README.md)，路由与参数见 [后端接口说明](后端接口说明.md)，历史专项与当前验收入口见 [文档索引](文档索引.md)。本轮没有重新连接服务器或平台。

## 实现与评审稿的区别

后端与数据库遵循 Python、FastAPI、SQLite 的既定选择。为压缩首版复杂度，员工、客户和群资料合并为 `profiles` 快照表，由 `tenant_id + kind + external_id` 唯一约束区分；客户的员工关系信息保存在客户快照的 `follow_user` 中。业务事件保存外部实体 ID 和历史展示快照，不对不同企业的相同 ID 做跨主体关联。

当前模型包含 tenants、app_users、user_tenants、auth_sessions、profiles、media_assets、callback_inbox、processing_jobs、business_events、audit_logs 共 10 张业务表，另有 Alembic 版本表。初始迁移使用冻结的 `migrations/schema_v1.py`；`0002_customer_groups` 使用冻结的 `migrations/group_classification_v2.py` 重分类历史群事件并保存降级恢复数据。`0003_profile_capture_version` 为资料表新增群采样版本，升级已有资料时置零并保留原名单及采样完成时间。后续修改应用模型或分类函数不会改变历史迁移。

前端采用 Vue 3、TypeScript 和 ECharts，表单与响应式布局使用原生组件和 CSS，没有增加 Vant 依赖。五个导航为汇总、新增、删除、群变更、我的；移动端底部导航、桌面侧栏共用 SVG 图标。界面主题集中在设计变量和图表主题中维护。

2026-10-26 调整新增、删除、群变更页的筛选布局：主体和统计区间位于筛选卡第一行，搜索、员工选择、添加方式或群类型位于第二行，控件统一高度并按卡片可用宽度换行（包含助手展开的窄主内容区）。记录数与人次放在列表标题旁，搜索和筛选规则不变。列表页底部时间说明靠近吸底分页，短列表利用剩余高度下移，长列表随内容排列并预留分页空间；仅汇总页显示“每 30 秒更新汇总”，列表页不承诺自动刷新。

新增、删除列表按自身内容宽度切换展示：可用宽度达到 860px 时显示浅底色表头，列标题 15px/600 字重，提供至少 52px 的表头高度；客户、员工/主体、时间与数据行使用同一列布局，避免表头贴边或错位。小于该宽度时隐藏列头并恢复卡片式信息排列，助手展开后的窄内容区使用相同规则，不只按浏览器窗口判断。

新增、删除按员工姓名或 ID 直接搜索事件，可叠加指定员工、添加方式及主体/日期；群变更按有效展示群名搜索。新增、删除和群变更均采用上一页/下一页，显示总条数、页码及每页 10/20/50 条（默认 20）；分页吸附视口底部，手机位于底部导航上方并为正文保留占位。翻页固定首屏最大 ID 和实际日期，失败保留当前页，刷新或筛选后从第一页查询。原上拉追加已按用户选择替换，下拉刷新保留。

事件列表与助手事件明细的总条数、总人数和当页记录在同一条 SQL 中读取；空页也返回同一查询快照的总数。游标中的旧汇总值不再作为查询依据。首屏最大 ID 仅排除后续插入，已有事件在重试时的重分类、数量变化或分组删除会反映到后续请求，跨页不承诺历史版本冻结；后续新拆分的记录也须刷新首屏才会纳入。为保证一致性，每次翻页重新聚合，后续优化不能直接恢复旧游标汇总复用。

汇总图表保留图例隐藏状态，跨手机/桌面断点调整大小；1800px 起扩展工作区和明细列布局，2200px 起汇总采用指标/趋势与排名左右分区。个人中心显式刷新资料及授权，失去全部授权显示无权限页并清空旧数据。退出、过期及迟到响应按会话代次隔离；显式刷新可重试失败头像，30 秒汇总轮询不触发图片自动重试。返回各页签恢复页码/筛选、URL 分享定位尚未新增。

目前只有一种“处理回调”任务，补全资料及头像在任务中重试；不引入额外任务系统。初次资料快照通过 CLI 同步。关键流程持久化，不依赖 FastAPI 进程内 BackgroundTasks 的执行保证。

与评审设计相比，当前会话表保存令牌哈希、CSRF 值、到期时间和撤销标记；没有独立的 `csrf_hash`、`revoked_at` 字段。事件中的员工、客户、群及操作人 ID 为外部字符串标识，不是本地资料表整数外键。收件箱未保存独立的去重版本，任务以 `callback_id` 唯一约束保证一个回调对应一个任务。审计表记录操作者、动作、目标与时间，未实现评审稿中的完整请求上下文与详情字段。

任务单次处理超时 120 秒，包含领取后的资料加载、载荷解密、JSON 解析及事件处理；领取租约 180 秒，租约过期可重新领取。上述处理失败统一按 `min(300000, 2000 × 2^attempts) + 0～1000` 毫秒退避，第 5 次尝试仍失败后标记 `failed`，同步收件箱状态、清除租约并记录脱敏错误。连续崩溃导致处理预算耗尽的任务，在再次领取时直接收敛为失败；取消保留租约供恢复。完成回写须匹配领取时的尝试次数和租约，旧执行者不能覆盖已被重领任务的状态；这不代表已实现同群任务串行或完整多消费者安全。当前没有按永久错误单独提前终止。管理员可重试 `retry` 或 `failed` 任务，重试会将尝试次数归零。管理接口仅返回最近 100 个任务。

## 统计口径

- 新增和删除按关系变更人次统计；删除包含两个方向，文案保留方向。
- 删除员工排名包含两个方向，应由业务方确认是否符合考核口径。
- 主动退群排名不包含被移出群。
- 未手动设置日期时，指标与排名近 7 天，趋势近 30 天；手动日期范围应用于全部图表及明细。
- 上期为等长的前一个自然日区间，今天截至当前的累计值与上一完整区间比较；页面标注更新时间。
- 群变更只有数量时按 quantity 保存在待核实列表；明细区分记录条数和平台报告人数。
- `unresolved_count` 统计 `group_change_unknown` 的 quantity，包含内部员工和证据不足部分；已归类的 inferred 外部客户计入业务指标，不重复计入此数。
- 未确认外部联系人成员身份的群变更，不计入已确认退群或被踢指标；已知的退出原因保留为 reported_event_type。
- 日期按北京时间自然日计算，首尾日期均包含在内，允许 1～366 天；仅填结束日期时向前取默认天数，仅填开始日期时结束日期为今天。
- 页面总览在登录、页面可见且未加载时每 30 秒刷新；明细页通过切换筛选、手动刷新或下拉刷新更新。

以上口径可配置性尚未单独产品化，调整需要修改接口逻辑及对应测试，应先完成公司评审。

## 回调和平台边界

目前实现企业微信企业内部回调格式及钉钉企业内部 H5 免登，不支持服务商 SuiteTicket、企业授权回调或第三方应用授权流程。

回调使用解密后的完整规范化载荷摘要去重，数据库唯一约束防止并发重复入库；不同客户在同秒发生的事件不会被误合并。但在平台未提供唯一 ID 且两个真实事件载荷完全相同的情况下，无法无条件区分重投与新事件。

成员资料可能因权限或关系删除而不可获取，系统优先采用已有快照；获取不到时事件仍入库，状态为 partial，并保留失败任务供重试。历史事件不通过现有客户列表伪造。

群变更在有效快照比对、人数一致且可关联成员时，按外部联系人类型与退出原因归入 group_left/group_removed，保留 resolution=inferred，计入列表和四项指标。混合变更拆分客户与内部/未知部分并保持总人数；无法关联、类型或退出原因未知的记录保留 group_change_unknown。回调有完整文本 `MemChangeList` 时，还须与差异成员集合、数量和唯一性一致；冲突保留待核实。详情说明依据，群主不冒充操作人，也不按同名或同头像合并身份。历史数据通过 0002_customer_groups 迁移重分类，见 [客户事件分类与识别依据](群成员识别状态.md)。

群资料同步、建群及成员进群回调先持久化成员名单，再按同主体真实成员 ID 补全资料和头像；并发上限 3，单群头像预取预算 80 秒。每次群详情请求前通过短事务递增同主体同群的 `capture_version`，响应和头像预取写回必须匹配该版本；慢返回的旧请求不能覆盖较新请求的快照，同一毫秒也可区分。`synced_at` 仍记录详情响应完成时间，用于判定事件前基准；预留版本不刷新历史名单或该时间。较新请求失败时保留上次完成的快照，并拒绝更旧在途请求的迟到写入，等待后续同步重试。资料创建和更新使用原子 upsert，避免并发首次写入冲突。

离群后优先使用历史 Profile 和成员快照的媒体引用；下载失败保留重试状态，平台未提供头像与下载失败分别展示。HTTP 腾讯头像来源按规则升级 HTTPS，下载不跟随重定向，保留来源、大小及图片签名限制。媒体文件先完整写入同目录临时文件后原子发布，已有文件不重写；媒体行按主体及内容摘要原子去重，同头像并发下载返回同一媒体 ID，下载和文件发布均在数据库事务外。

## 部署与维护边界

单机、单 Uvicorn worker、单后台消费者。本期没有分布式协调或横向扩展；SQLite 文件不应放网络共享文件系统。数据库和媒体需持久化，.env 及 PAYLOAD_KEY 独立安全保存。

当前未添加自动保留期清理，以避免在公司尚未确认期限时删除数据。正式上线前需要确认原始回调、会话、日志、头像和备份保留策略，并安排磁盘监控及备份执行。

管理员页面支持主体配置、启停、普通用户创建、主体授权和任务重试；首位管理员由 CLI 创建。角色升级和用户停用尚未提供单独管理界面，不能把这两项算作已交付功能。

新增主体允许凭据尚未就绪；管理页的 `credentials_ready` 只检查 Secret、Token、AESKey 是否非空，不校验格式、归属或平台权限。主体创建后不能通过现有更新接口更改 CorpID。`create-admin` 遇到已存在用户时不会提升其权限。停用主体后不再接收其回调或展示其业务数据，但已存在任务仍可能被领取，并以 `tenant_disabled` 进入重试或失败状态。

直接运行 Uvicorn 前必须执行迁移；应用启动只检查已有表，不自动建表。容器入口会先运行 Alembic，再启动单 worker。`/healthz` 仅检查进程响应；`/readyz` 检查数据库连接，并在启用消费者时检查其最近循环时间是否超过 180 秒，不代表平台权限或全部任务处理成功。宝塔 Compose 配置使用 `/readyz` 健康检查，默认 Caddy Compose 未配置容器健康检查。

已有源码发布、公网资源核对、真实钉钉免登、受控退群/移出与历史头像以及部分 PC/Android 交互验收记录，见 [真实钉钉环境验收记录](真实钉钉环境验收记录.md)。小米14和3440×1440钉钉PC的通过反馈只覆盖已记录的路径，不扩大到 iOS、所有缩放比例、真实多页或全新客户冷缓存。

截至 2026-10-23 的最后只读复查，HTTP 未强制跳转 HTTPS，实际服务未启用生产模式和 Secure Cookie，仍有启用演示主体进入管理员合计的路径及历史补全失败。上述部署问题不能用源码支持生产校验或 HTTPS 可访问替代关闭。本轮没有在线复查，也未变更配置、主体或数据；完整待办见 [当前未完成项复查](需求1-8章当前未完成项复查.md)。员工本人授权头像、被移出操作人可靠来源、真实多主体/多页、自然会话过期及端侧性能仍需补齐。

2026-10-26 为应用内助手增加固定模板统计图：周报/区间分析自动展示本期与上期对比和删除方向构成，统计、每日趋势、排名查询展示对应图表。浏览器仅使用已授权接口的结构化数字，不解析模型正文、不执行模型生成的代码；趋势和排名标明分页范围，单条事件及资料名单不绘制无关区间图表。图表范围、使用方法与本地验证见 [AI 助手使用与接入](AI助手使用与接入.md#2026-10-26-助手统计图表)。

2026-10-24 新增应用内客户分析助手，入口位于右上角及事件详情；复用已授权的统计与事件查询，支持 vLLM 最终文本生成及规则回退。群列表问题直接查询已同步群资料，与 `/groups` 共用筛选及排序逻辑，支持分页、关键词和同步时间展示，不将群资料送模型，也不将资料列表当作企微实时全量群。助手为只读接口，数字卡片和明细来源由服务端生成，不变更业务分类；对话仅存当前页面内存，审计不保存问题/回答。实现、配置、隐私范围和验证见 [AI 助手使用与接入](AI助手使用与接入.md)。本节下文为项目开发过程中的 AI 辅助记录，与应用内助手是不同事项。

同日扩展至 21 类受控数据工具，覆盖现有业务资料与管理元数据；`app/assistant_data.py` 负责查询参数、能力注册、角色校验和白名单结果，页面与助手共享事件筛选。模型可解析复杂问题为经过校验的 JSON 参数，不接收资料名单，不执行 SQL；前端提供类型选择、筛选、翻页、关联记录与头像查看。管理员全局元数据、当前授权主体业务数据和本人会话信息分别按原权限边界执行，原始回调、会话令牌和密钥不开放。

本次使用 AI 辅助完成后端、前端、迁移、测试和文档初稿，并根据执行结果修正 SDK 调用方式、登录后页面状态、头像补全重试及员工跨主体筛选。代码与文档需要开发者阅读理解，并在试岗答辩中解释关键设计及已知边界。不得将模拟测试或未完成的真实联调描述为已通过。
