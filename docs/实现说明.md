# 当前实现范围和技术决策

代码核对日期：2026-10-22。本文描述当前行为；[第 1 天技术方案](第1天技术方案.md) 中的排期、细分表设计和增强能力保留为历史评审内容。操作入口见 [README](../README.md)，路由与参数见 [后端接口说明](后端接口说明.md)。

## 实现与评审稿的区别

后端与数据库遵循 Python、FastAPI、SQLite 的既定选择。为压缩首版复杂度，员工、客户和群资料合并为 `profiles` 快照表，由 `tenant_id + kind + external_id` 唯一约束区分；客户的员工关系信息保存在客户快照的 `follow_user` 中。业务事件保存外部实体 ID 和历史展示快照，不对不同企业的相同 ID 做跨主体关联。

本地数据库实际包含 tenants、app_users、user_tenants、auth_sessions、profiles、media_assets、callback_inbox、processing_jobs、business_events、audit_logs 共 10 张业务表，另有 Alembic 版本表。初始迁移使用冻结的 `migrations/schema_v1.py`，后续修改模型不会改变历史迁移。

前端采用 Vue 3、TypeScript 和 ECharts，表单与响应式布局使用原生组件和 CSS，没有增加 Vant 依赖。页面包含移动端底部导航、桌面侧边导航、下拉刷新、加载更多和错误状态。

目前只有一种“处理回调”任务，补全资料及头像在任务中重试；不引入额外任务系统。初次资料快照通过 CLI 同步。关键流程持久化，不依赖 FastAPI 进程内 BackgroundTasks 的执行保证。

与评审设计相比，当前会话表保存令牌哈希、CSRF 值、到期时间和撤销标记；没有独立的 `csrf_hash`、`revoked_at` 字段。事件中的员工、客户、群及操作人 ID 为外部字符串标识，不是本地资料表整数外键。收件箱未保存独立的去重版本，任务以 `callback_id` 唯一约束保证一个回调对应一个任务。审计表记录操作者、动作、目标与时间，未实现评审稿中的完整请求上下文与详情字段。

任务单次处理超时 120 秒，领取租约 180 秒，租约过期可重新领取。失败按 `min(300000, 2000 × 2^attempts) + 0～1000` 毫秒退避，第 5 次尝试仍失败后标记 `failed`；当前统一重试处理失败，没有按永久错误单独提前终止。管理员可重试 `retry` 或 `failed` 任务，重试会将尝试次数归零。管理接口仅返回最近 100 个任务。

## 统计口径

- 新增和删除按关系变更人次统计；删除包含两个方向，文案保留方向。
- 删除员工排名包含两个方向，应由业务方确认是否符合考核口径。
- 主动退群排名不包含被移出群。
- 未手动设置日期时，指标与排名近 7 天，趋势近 30 天；手动日期范围应用于全部图表及明细。
- 上期为等长的前一个自然日区间，今天截至当前的累计值与上一完整区间比较；页面标注更新时间。
- 群变更只有数量时按 quantity 保存在待核实列表；明细区分记录条数和平台报告人数。
- 未确认外部联系人成员身份的群变更，不计入已确认退群或被踢指标；已知的退出原因保留为 reported_event_type。
- 日期按北京时间自然日计算，首尾日期均包含在内，允许 1～366 天；仅填结束日期时向前取默认天数，仅填开始日期时结束日期为今天。
- 页面总览在登录、页面可见且未加载时每 30 秒刷新；明细页通过切换筛选、手动刷新或下拉刷新更新。

以上口径可配置性尚未单独产品化，调整需要修改接口逻辑及对应测试，应先完成公司评审。

## 回调和平台边界

目前实现企业微信企业内部回调格式及钉钉企业内部 H5 免登，不支持服务商 SuiteTicket、企业授权回调或第三方应用授权流程。

回调使用解密后的完整规范化载荷摘要去重，数据库唯一约束防止并发重复入库；不同客户在同秒发生的事件不会被误合并。但在平台未提供唯一 ID 且两个真实事件载荷完全相同的情况下，无法无条件区分重投与新事件。

成员资料可能因权限或关系删除而不可获取，系统优先采用已有快照；获取不到时事件仍入库，状态为 partial，并保留失败任务供重试。历史事件不通过现有客户列表伪造。

群变更当前不尝试不可靠的成员差集归因；普通回调只提供数量时保存聚合记录，并标记 unresolved。因为总人数可能包含内部成员，记录进入待核实列表，不计入四项指标中的已确认外部联系人退群或被踢数量。具体成员级处理和操作人补全需要拿到公司真实样本与可用数据源后实现。模拟数据中的成员明细仅用于演示界面。

## 部署与维护边界

单机、单 Uvicorn worker、单后台消费者。本期没有分布式协调或横向扩展；SQLite 文件不应放网络共享文件系统。数据库和媒体需持久化，.env 及 PAYLOAD_KEY 独立安全保存。

当前未添加自动保留期清理，以避免在公司尚未确认期限时删除数据。正式上线前需要确认原始回调、会话、日志、头像和备份保留策略，并安排磁盘监控及备份执行。

管理员页面支持主体配置、启停、普通用户创建、主体授权和任务重试；首位管理员由 CLI 创建。角色升级和用户停用尚未提供单独管理界面，不能把这两项算作已交付功能。

新增主体允许凭据尚未就绪；管理页的 `credentials_ready` 只检查 Secret、Token、AESKey 是否非空，不校验格式、归属或平台权限。主体创建后不能通过现有更新接口更改 CorpID。`create-admin` 遇到已存在用户时不会提升其权限。停用主体后不再接收其回调或展示其业务数据，但已存在任务仍可能被领取，并以 `tenant_disabled` 进入重试或失败状态。

直接运行 Uvicorn 前必须执行迁移；应用启动只检查已有表，不自动建表。容器入口会先运行 Alembic，再启动单 worker。`/healthz` 仅检查进程响应；`/readyz` 检查数据库连接，并在启用消费者时检查其最近循环时间是否超过 180 秒，不代表平台权限或全部任务处理成功。宝塔 Compose 配置使用 `/readyz` 健康检查，默认 Caddy Compose 未配置容器健康检查。

真实平台联调、公司环境部署、真实数据规模的性能验收，以及移动端钉钉容器兼容性，仍须在取得公司配置后执行。
