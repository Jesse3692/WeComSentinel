# 企微用户流失监控技术方案

版本：第 1 天评审稿 v1.0  
编制日期：2026 年 10 月 21 日  
后端与数据库：Python + FastAPI + SQLite  
交付周期：5 天，实际起止日期和每日验收时间待公司确认。

本项目建设钉钉工作台 H5 应用，接入多个企业微信主体的客户关系与群变更数据，提供汇总、趋势、排名和明细查询。采用单实例服务与本地数据库，在五天内优先完成真实回调、可靠入库、统计一致性和权限隔离，再完成页面及部署验收。

本方案用于技术评审与开发排期，不代表功能已实现或联调已通过。Python、FastAPI、SQLite 已按开发者要求确定；前端选型、统计口径及平台能力边界按下文评审确认。

## 二 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python + FastAPI + Uvicorn | 与开发者技术栈一致，接口采用 Pydantic 模型校验并生成 OpenAPI |
| 数据访问 | SQLAlchemy 2 + aiosqlite | 使用异步数据库会话；每个请求、后台任务单独创建会话 |
| 数据库 | SQLite | 单机文件持久化，开启 WAL，控制写事务长度 |
| 数据迁移 | Alembic | 提交版本化迁移；涉及 SQLite 改表时使用适合其能力的批处理迁移 |
| 第三方请求 | httpx | 统一超时、错误处理、连接复用、受控重试 |
| 回调解析 | 经验证的企微加解密实现、安全 XML 解析器 | 按官方协议验签与解密，不自行设计加密算法；禁用外部实体 |
| 前端建议 | Vue 3 + TypeScript + Vite + Vant + ECharts | 适配移动 H5；PC 采用响应式布局。已有前端可复用时优先复用 |
| 后台处理 | SQLite 持久化任务表 + 单消费者 | 无需 Redis、Celery；重启后可继续处理未完成任务 |
| 登录态 | 随机会话令牌 + SQLite 会话表 | 服务端存令牌哈希；支持立即注销和授权变更生效 |
| 文件存储 | 本机持久化目录 | 客户头像按主体隔离，经鉴权接口访问 |
| 测试与质量 | pytest、HTTPX 测试客户端、Ruff | 验证去重、恢复、权限、统计和日期边界 |
| 部署 | 单实例 Uvicorn + HTTPS 反向代理 | 优先使用公司已有反向代理与进程管理；可提供 Docker 配置 |

依赖版本在第 1 天通过安装和兼容性验证后锁定；记录 Python 运行时实际链接的 SQLite 版本，并采用包含适用安全及正确性修复的版本。

SQLAlchemy 的异步会话不能在并发任务间共享，因此数据库依赖按请求和任务隔离。[SQLAlchemy 官方说明](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)

### SQLite 运行约束

建议连接配置如下，最终通过目标服务器测试确定：

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = FULL;
```

WAL 在数据库初始化时设置；外键、等待时间及同步配置在每个连接上落实。服务使用一个 Uvicorn worker 和一个后台消费者。数据库放在本地持久化磁盘，不放网络共享盘。WAL 允许读写并行，但同一时刻仍只有一个写入者，因此接口写入与后台写入均使用短事务；第三方请求和头像下载必须在事务外执行。[SQLite WAL 文档](https://sqlite.org/wal.html)

锁等待超时后有限重试；仍不能可靠保存回调时不得返回业务成功。记录锁冲突、积压量、磁盘空间和最老任务等待时间。单实例与低到中等写入压力是本期部署前提，具体容量以验收压测为准。

数据库通过在线备份 API 生成一致性备份，不能只复制运行中的主数据库文件；头像目录一并备份，恢复演练检查引用完整性。[SQLite 备份文档](https://sqlite.org/backup.html)

## 四 核心处理流程

### 回调接收和可靠处理

1. 回调地址包含主体配置标识，服务端读取对应密钥，验签、解密并核验消息所属企业。地址中的主体标识本身不构成信任依据。
2. 校验必需字段，生成去重键。在同一短事务内写入 callback_inbox 和 processing_job，提交后按平台协议响应。
3. 重复投递命中已有记录时不再创建任务。无效签名、解密失败、所属企业不符时拒绝处理。
4. 后台消费者原子领取到期任务，设置租约；在事务外补全资料，然后在短事务中写入业务事件并更新任务状态。
5. 对暂时性网络错误、限流等使用带抖动的退避重试；永久权限或配置错误标记失败，供管理员处理。重启时回收租约过期的任务。
6. 资料暂缺但事件类型与数量可信时，保留事件并标记 partial；不能把缺少头像当作丢弃事件的理由。补全成功后更新原记录，不重复计数。

持久化任务表是恢复依据，不单独依赖进程内 BackgroundTasks 保证任务可靠性。[FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)

去重优先使用平台提供的可靠事件标识；没有可靠标识时，使用“主体 + 完整规范化业务载荷”的摘要，排除传输重试参数，并保留去重版本。不得只按“主体 + 秒级时间”去重。若两个真实事件载荷完全一致，单靠摘要无法区分，须用真实样本验证并向公司说明边界，不承诺无条件精确一次。

### 资料快照和群变更

接入时初始化可访问的员工、客户及群成员快照。新增、资料变更时刷新快照，事件保留当时的展示信息；后续改名不应改写历史操作含义。快照初始化不是历史事件恢复。

删除记录保存 employee_deleted_customer、customer_deleted_employee 或 unknown，页面根据方向生成文案。客户资料获取失败时使用已有快照，无法恢复的字段显示“未知”，保留失败原因。

群变更的成员身份、退出原因、操作人字段需要第 1 天真实验证。若平台不能直接提供成员列表，可评估前后群成员差集，但差集仅是推断：连续变更、乱序或快照未初始化时可能无法准确对应人和事件。每个群串行处理，延迟读取并复核详情，记录快照版本和可靠性；不把群主当作默认踢人操作人。

若只有人数可信，则保留一条带数量的待核实事件，不生成虚构成员。后续解析出成员时，在同一事务中将该聚合记录标为 superseded，再新增成员记录，保证两者不重复统计。未知退出原因不强行归入退群或被踢。是否接受此降级展示必须由公司确认，它不等同于满足原始完整明细要求。

### 钉钉免登和授权

前端通过钉钉支持的免登流程取得临时凭证，后端向平台验证并换取企业内身份；不接受前端自行提交 userid 作为登录依据。具体流程按公司应用类型和当前平台接口验证。

登录成功后设置 Secure、HttpOnly 会话 Cookie，默认同源部署，服务端会话有效期为 2 小时。写操作校验 CSRF token 和来源；Cookie 的 SameSite 策略在钉钉移动端与 PC 容器实测后确定。过期返回 401，前端重新走免登；退出立即吊销会话，并停留在退出页，避免立刻自动登录。

所有查询按当前用户的授权主体集合过滤；管理员可访问所有启用主体，普通用户只能访问授权主体。单条事件、头像、筛选候选项和管理接口同样校验权限；取消授权后下一次请求立即生效。

## 五 数据库表设计

### 通用约定

- 主键采用 SQLite INTEGER PRIMARY KEY。外部 ID 使用 TEXT，保留原值和大小写。
- 时间使用 UTC Unix 毫秒 INTEGER；显示与按日分组使用 Asia/Shanghai。外部秒级时间转换后保留来源精度，不伪造毫秒精度。
- JSON 存为 TEXT，经 Pydantic 校验。状态字段采用 TEXT + CHECK；布尔字段使用 INTEGER + CHECK 限制为 0 或 1。
- 业务表必须有 tenant_id；外部用户与群 ID 的唯一性只在对应主体内成立。
- 表中除特别说明外，标识、状态、创建时间非空；资料字段允许 NULL。所有实体表含 created_at、updated_at；仅追加日志保留 created_at 即可。
- 同主体关联使用复合唯一键和复合外键约束，服务层再次校验；主体、用户默认停用，不级联删除历史事件。

### 配置与权限

| --- | --- | --- |

| app_users | id INTEGER；ding_corp_id TEXT；ding_user_id TEXT；name TEXT 可空；avatar_url TEXT 可空；role TEXT；enabled INTEGER；last_tenant_id INTEGER 可空 | UNIQUE(ding_corp_id, ding_user_id)；role 为 admin 或 user；恢复上次主体前重新验权 |

初始索引：

```text
(tenant_id, occurred_at DESC, id DESC)
(tenant_id, event_type, occurred_at DESC, id DESC)
(tenant_id, employee_id, event_type, occurred_at)
(tenant_id, group_id, event_type, occurred_at)
```

不预先增加每日汇总表：初期从业务事件直接聚合，减少明细与统计分叉。根据真实数据量和 EXPLAIN QUERY PLAN 再调整索引；不承诺普通索引能加速任意群名包含搜索。

## 六 统计规则与接口规划

### 统一统计口径

1. 默认近 7 天含当天，日期采用北京时间自然日，后端转换为 UTC 左闭右开区间。
2. 上期为当前区间之前等长区间；变化量为本期数量减上期数量，不使用百分比。当天尚未结束时标注“截至当前”，同比较口径待确认。
3. 新增与删除按客户和员工的关系变更次数统计，同一客户与不同员工的关系分别计数。
4. 拟将删除卡片合计两个删除方向，并在明细标识方向；删除 Top 5 是否同样合计由公司确认。
5. 拟将退群 Top 5 仅统计主动退出，被踢单独计数。跨主体排名按主体与员工或群 ID 组合分组，不按姓名合并。
6. 拟默认趋势为近 30 天，用户主动选择日期后跟随日期范围；与原文“固定近 30 天”的冲突需确认。缺失日期补零。
7. 看板和明细复用同一权限与过滤条件，统计仅针对 active 记录并 SUM(quantity)。存在聚合记录时，明细同时返回记录条数和事件人数，避免将两者混淆。
8. 未确定退出原因的事件单独标记，不混入四项指标；显示待核实数量。存在待核实事件时不能声称四项指标已经完整。
9. 排名按数量降序，再按主体及实体 ID 稳定排序，取前 5 项。

以上拟定口径在第 1 天评审后固定为测试样例。

### 查询参数和返回约定

| 参数 | 规则 |
| --- | --- |
| tenant_id | 单个主体 ID 或 all；all 仅表示当前授权集合 |
| start_date / end_date | YYYY-MM-DD，用户输入的结束日含当天；后端转换为次日零点的开区间 |
| event_type | 四种业务类型之一，待核实记录使用独立类型 |
| employee_id / add_way | 新增明细筛选；删除明细支持 employee_id |
| group_keyword | 群明细搜索，按约定使用事件快照群名 |
| cursor / limit | 默认 20 条，最多 100 条；参数边界由服务端校验 |

明细按 occurred_at DESC、id DESC 排序。第一页记录最大可见 id，后续页固定 id 上界，并使用上一条的时间和 id 翻页；游标绑定筛选摘要并签名。这样新插入或迟到入库记录不会混入同一次翻页。授权每次重新检查；下拉刷新开启新分页视图。聚合记录解析等更新可能改变结果，页面提示刷新，不声称跨页数据库快照。

成功响应采用 data、request_id；错误响应采用 error.code、error.message、request_id。使用 401 表示未登录或过期、403 表示无权限、404 表示不可见资源、422 表示参数错误、503 表示暂不可用。空数据返回空数组或零值，不能用成功空列表掩盖后端错误。

## 七 安全和验证计划

### 安全措施

- 全站 HTTPS，同源部署；密钥由环境或受控配置提供，数据库、头像和 .env 不进 Git。
- 数据库文件、备份和头像目录限制服务账号访问。原始载荷设置保留期限，管理操作和异常访问留审计记录。
- 图片仅从已验证的平台返回地址下载；校验协议、域名和解析地址，阻止内网地址及不安全重定向，限制体积、类型和超时。文件名由服务端生成。
- SQL 使用参数化查询，前端按文本渲染外部昵称；回调限制请求体大小，禁用 XML 外部实体。
- 不信任前端传入的 tenant_id、角色、userid 和媒体路径；所有数据访问在服务端验证。

### 重点自测

| 场景 | 预期结果 |
| --- | --- |
| 同一回调重复投递、任务重复执行 | 事件人数和记录不重复累加 |
| 持久化后进程退出、任务运行中退出 | 重启后任务恢复，无重复事件 |
| 数据库锁等待、磁盘写入失败 | 未持久化不响应成功，保留可诊断错误 |
| 两个主体使用相同外部 ID | 数据隔离，查询与媒体访问均不串主体 |
| 普通用户修改 tenant_id、事件 ID、媒体 ID | 无法访问未授权数据 |
| 注销、过期、取消授权 | 后续请求失效或权限立即收紧 |
| 员工删客户、客户删员工 | 删除方向和文案正确 |
| 群退出与踢人、连续群变更 | 区分已证实和未知字段，不虚构操作人 |
| 无历史快照、资料接口失败、头像失效 | 事件保留，缺失状态可见且可重试 |
| 跨月、跨年、上期为空、零数据 | 数量、变化量和补零正确 |
| 切主体时旧请求晚返回 | 不覆盖新主体页面 |
| 迟到事件和分页期间新增 | 同次翻页不因新增而重复，刷新后可见新记录 |
| 聚合事件解析为成员记录 | 原记录替换与成员写入同事务，不重复计数 |
| 备份恢复 | 数据库可打开，事件及头像引用一致 |

验收报告逐项记录输入样本、预期值、实际值和截图或日志。模拟数据与真实回调结果分开标记；性能记录数据规模、并发、设备和多次测量结果。
