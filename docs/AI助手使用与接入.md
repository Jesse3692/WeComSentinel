# 客户分析助手：使用、模型接入与验证

实现日期：2026-10-24。本功能为只读分析助手，支持 vLLM 兼容的 Chat Completions 接口。不修改客户资料、不发送消息、不重试后台业务任务。已有业务分类、回调流程和数据库表结构保持原有规则。

## 页面入口与交互

- 登录后，页面右上角提供「✦ AI 助手」。电脑宽度大于 1100px 时展开右侧 400px 面板，主内容缩窄；761～1100px 使用遮罩抽屉；手机使用全屏对话，原底部导航暂时隐藏。
- 事件详情提供「✦ 让助手解释」，带入事件所属主体与事件 ID，自动发起解释。事件解释不受当前日期筛选限制，回答依据显示该事件的发生时间。
- 从助手点击「事件详情」或事件依据时，保留助手对话、未发送输入和滚动位置，在上层显示详情；手机为全屏详情。关闭、Esc 或「返回助手」只收起详情，焦点回到原事件入口。加载失败在助手内提供重试，不因单条事件不存在就关闭助手；退出登录及权限失效仍按原规则清理。
- 已有助手对话时，详情中的「让助手解释」会在当前对话追加指定事件的解释并保留输入；助手生成中暂不可追加。助手未打开时仍进入该事件的独立上下文。交互与实现见 [事件详情交互改造方案](AI助手事件详情交互改造方案.md)。
- 对话支持快捷提问、输入问题、Enter 发送（Shift+Enter 换行）、停止生成、新对话、失败重试、Escape 关闭。手机输入区域根据可视视口变化调整位置。
- 普通事件解释、数据查询和分析不添加「草稿」标题；只有明确生成日报、周报或报告时才标注草稿。电脑和手机共用同一规则；开头误加的装饰性草稿标签会被清理，正文中的真实含义、待核实状态和推断依据保留。
- 回答包含文本、服务端统计卡片、实际统计及对比日期、查询时间和可点击的事件依据。模型解释事件时，先展示服务端生成的「系统识别依据」，再展示模型分析，避免以模型文字代替系统分类结论。统计查询的依据仅列最近 5 条样本，不能当作完整统计清单；点击重新调用授权事件详情接口。
- 对话仅保留在当前页面内存，最多 20 轮；不写入 localStorage、sessionStorage 或数据库。切换主体、日期、事件上下文或授权范围时清空对话，退出登录后销毁。关闭面板保留当前上下文对话。
- 「查询内容」选择框列出当前角色可用能力，可直接选择后查询；列表结果支持关键词、翻页、查看更多字段、查看相关事件、跟进员工、群详情/成员或本地头像。对象同名或跨主体 ID 重复时先返回候选，要求明确选择，不自动合并。

## 能力与统计边界

1. 当前区间四类指标与上一等长自然日区间比较，复用看板统计逻辑。助手绕过看板短缓存，读取本次查询的数据，避免删除方向与缓存汇总混用。刚有新事件时，看板可能在下一次缓存失效或轮询后才与助手一致。
2. 删除拆分为客户删除员工、员工删除客户和方向未提供。数量均为人次/关系变更人次，不代表独立客户数。
3. 主动退群、被移出群、其他/待核实分开统计；inferred 保留为快照推断，不宣称平台逐人确认；内部员工不计外部客户流失。
4. 可解释已授权事件的业务分类、识别依据、资料补全状态和操作人是否提供；不把群主当操作人。
5. 支持报告草稿和当前区间 Top 5 排名。排名复用看板现有口径：新增员工、删除员工、主动退群群聊；删除排名包含两个删除方向。
6. 默认使用页面区间。识别 YYYY-MM-DD、今天、昨天、本周/这周、上周和近 N 天（1～366）；本周为周一至今天。对比使用上一等长区间，今天尚未结束时仍与上一完整区间比较。每个回答展示实际采用的区间，不能只依据问题中的“本周”判断。
7. 提问「当前主体中有哪些群」「查看群列表」「当前主体有几个群」时，直接读取当前授权主体下本地保存的群资料，展示群名、所属主体和每条资料的同步时间。默认每页 20 个，支持上一页/下一页、群名称关键词筛选，以及「群名包含“关键词”的群」提问。群列表不受统计日期筛选，不通过群变更事件或匿名排名拼凑；未同步资料不等于企微没有群，本地资料也不能保证是企微此刻全部有效群。此类回答标作「数据查询」，无需模型生成。

现有资料不能证明客户退出的具体动机，也不能支撑可靠的未来流失概率。模型可提出明确标注为建议的排查项；没有跟进、交易或聊天资料时不能把它们称为已确认原因。本版没有任意 SQL、任意工具执行、向量知识库或自动运营动作。模型输出仍需结合服务端卡片与事件依据核对。

## 复用现有 vLLM

在服务器或本机 `.env` 中配置，修改后重启后端。服务地址由运维固定配置，前端不能传入模型地址；应填写部署后端能够访问的地址。

```dotenv
ASSISTANT_ENABLED=true
ASSISTANT_BASE_URL=http://你的模型服务器:8099/v1
ASSISTANT_MODEL=qwen35-122b-local
ASSISTANT_API_KEY=
ASSISTANT_TIMEOUT_SECONDS=45
ASSISTANT_MAX_TOKENS=1200
```

模型名称须与 vLLM `/v1/models` 返回的服务别名一致。用户当前服务未设置密钥，因此密钥留空，后端不会发送 Authorization 头。以后开启鉴权只需填写该字段；不要把密钥写入源码或前端配置。留空 `ASSISTANT_BASE_URL` 时使用规则查询，界面明确标注「规则查询模式」；`ASSISTANT_ENABLED=false` 关闭接口功能，界面打开后显示未启用。

后端通过现有 httpx 调用 `<ASSISTANT_BASE_URL>/chat/completions`，无需新增模型 SDK。请求使用单条开头 system 消息与单条 user 消息，以兼容当前 Qwen 模板；发送 `chat_template_kwargs.enable_thinking=false`。只展示最终 content，剔除完整 think 块，不展示 reasoning_content；未闭合 think、空内容、超长响应、输出截断、超时和 HTTP 错误均回退为规则结果并显示提示。没有自动重发，以限制模型请求开销。

协议来源：[vLLM 兼容服务说明](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)、[vLLM 推理输出说明](https://docs.vllm.ai/en/stable/features/reasoning_outputs/)。具体请求格式以当前部署的实际响应和测试为准。

## 权限、数据与运维

- 两个接口均要求有效登录；POST 沿用 CSRF 和 Origin 检查。每次按服务端用户授权选择主体，跨主体事件以 404 隐藏。
- 模型调用前结束数据库事务。生成完成后再次检查用户启用状态、登录会话、角色与主体授权；中途退出或撤销授权，不返回已生成的业务结果。
- 发给模型的事实只含统计数字、匿名排名及白名单事件字段。排除客户/员工姓名、外部 ID、头像、原始快照、渠道参数、回调载荷与业务密钥。群列表查询直接返回给已授权用户，群名称、群 ID、主体名称和同步时间不送模型，群主及成员资料不在该查询中返回。其他模型提问中，用户主动输入的问题及最多 6 条历史问题会发送到所配置模型；不发送历史助手回答，以免旧主体数据随追问传播。
- 每个用户每分钟最多 10 次、同一用户同时 1 次、进程总计最多 4 次生成。当前单 worker 进程内限流，不是分布式配额。模型总超时默认 45 秒；响应体限制 256 KiB。
- 数据查询使用固定的 `DataQuery` 模型和已注册查询函数；模型可用时，复杂自然语言先经 vLLM JSON 模式解析为查询参数，解析最多等待 12 秒，失败使用可识别的规则路由。只将问题、有限历史问题和能力/schema 发给路由模型；不发数据库名单。解析结果仍须通过 Pydantic 白名单、长度/分页限制、角色和主体权限检查；不接受 SQL、URL 或额外字段。资料、名单、管理查询结果直接返回给已授权浏览器；既有报告和解释仍只将受限事实摘要用于模型生成。
- 业务事件筛选由页面与助手共享，新增助手筛选支持客户关键词/标识、群标识、删除方向、识别状态和资料状态。助手事件翻页固定实际日期与首屏最大事件 ID，签名分页参数绑定用户、主体和筛选，修改筛选后必须重新开始。
- 审计仅记录用户、`assistant.query`、主体 ID、模型/规则模式、模型报告的 token 用量与时间，不保存问题或回答。当前不提供费用计算或对话持久化。
- 「停止生成」会取消浏览器请求并忽略迟到结果，不保证 vLLM 已开始的推理同步终止；服务端仍受总超时和并发限制。关闭页面或停止生成后的已处理请求仍可能产生模型用量。
- 助手不可用不影响回调消费、看板和事件查询。未配置或故障回退均不会把规则文字标作模型回答。
