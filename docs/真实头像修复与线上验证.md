# 真实头像修复、部署与线上验证

日期：2026-10-23。使用已配置服务器，仅输出脱敏汇总。保留原业务分类、识别依据和主体隔离。

## 线上根因

客户资料保存了http://wx.qlogo.cn来源的真实头像地址，原下载器仅接受HTTPS，导致媒体库与文件为空，头像任务5次失败。服务器实际代码与本地一致，不能归因于未部署。员工user/get实际返回成功但无avatar/thumb_avatar；用户提供的官方说明明确新自建应用敏感字段需员工本人OAuth2手工授权，不能以客户头像或姓名匹配代替。

## 改动

- app/media.py新增normalize_avatar_url：仅对qpic.cn/qlogo.cn及其子域内的HTTP地址升级为HTTPS。所有下载仍使用HTTPS；拒绝其他域名、非法/异常端口、嵌入账号、控制字符和反斜杠，禁止跟随重定向。大小和图片签名限制保留。
- app/worker.py：客户资料接口不可访问时，尝试下载该身份已缓存的合规历史头像URL；不把旧客户关系当作新关系。更新失败保留旧图，avatar_state=retry即使有旧media_id也继续重试。
- 修复会话清理触发员工搜索请求、员工选项旧错误污染新页面，登录成功明确建立新请求代次；补充回归后随本次发布。
- scripts/backfill_avatars.py：默认仅预览，--apply前备份SQLite；只处理非demo且身份可关联的记录，仅补媒体引用和头像状态，不重放回调、不重新分类、不改人数和日期。

## 真实图片与客户端证据

- 从生产媒体目录只读取得实际下载的图片，以进程内字节交给Edge无头浏览器解码，不写本地客户照片，不打印照片内容或地址；complete=true，naturalWidth=940，naturalHeight=940。不是合成PNG或模拟头像。
- 用户随后提供线上新增联系人截图，真实客户照片已显示。
- 用户在钉钉客户端确认：“被移出群”一条显示同一客户照片，另一条仍占位。由此确认新增联系人与对应群变更的真实照片已在客户端显示。
- 电脑Edge现有应用页未登录，没有创建临时生产管理员会话，也没有将本地合成图验证当作钉钉客户端验证。

## 无法补回的历史头像与独立验收项

- 主动退群和另一条被移出群涉及不同客户，均无可用历史头像缓存；该客户资料请求返回84061。因此保留占位，不复用已取得客户的照片。不把这两条称为已恢复头像；需要该客户以后建立可访问关系或已有合法资料来源，才能重新补全。
- 员工头像：接口没有返回字段，需要员工本人OAuth2手工授权。此次未新增敏感字段授权流程，也未扩大权限或冒用钉钉头像。
- 新产生事件的持续采集、真实头像更新失败恢复、iOS/Android/PC全版本兼容与时效/容量验收，继续独立记录；此前用户确认的真实联调结论保留。

## 复现与后续维护

脚本预览：uv run python -m scripts.backfill_avatars；确认目标后执行uv run python -m scripts.backfill_avatars --apply。默认不处理演示记录；所有业务字段保持不变。生产执行前保留部署和avatar备份。数据不可获取时不要循环重放历史事件企图恢复身份或头像。

实际图片解码工具tests/live-avatar-decode.cjs从stdin接受媒体字节并只输出媒体ID和尺寸。artifacts/avatar-repair内运维脚本只读取本地已有SSH配置，不含凭据；后续使用前确认目标，不直接打印数据库个人信息。
