# 当前后端接口说明

代码核对日期：2026-10-24，源码基线 `24e6586`。依据 `app/api.py`、`app/main.py` 和 `app/models.py`。本文记录本系统接口，平台调用见 [企业微信与钉钉接口及配置说明](企业微信与钉钉接口及配置说明.md)。开发环境可访问 `/docs`、`/openapi.json`；生产环境关闭这两个入口。

## 通用约定

- 业务接口前缀为 `/api/v1`，成功响应为 `{"data": ...}`。健康检查和企微回调不使用此包装。
- 登录 Cookie 名为 `monitor_session`，有效期 2 小时，HttpOnly、SameSite=Lax；Secure 由 `COOKIE_SECURE` 控制，生产环境必须开启。
- 登录返回 `csrf_token`，已有会话可通过 `GET /me` 重新获取。所有需要登录的写接口须在 `X-CSRF-Token` 请求头提交该值。
- 非 GET、HEAD、OPTIONS 请求若携带 `Origin`，必须与 `PUBLIC_ORIGIN` 完全一致。同源访问方式见 [README](../README.md)。
- 管理员可访问所有启用主体；普通用户仅可访问已授权且启用的主体。授权撤销在下一次查询生效。事件详情、媒体和筛选候选项同样受权限限制。
- 已有会话无可访问主体时，汇总、事件列表、筛选候选和主体列表返回403；`GET /me`仍返回空主体列表供前端清理旧数据、显示无权限页面及正常退出。事件详情与媒体继续以404隐藏不可访问资源。前端刷新会重新核对`/me`，不再把零授权显示成零业务数据。
- 时间戳单位为 Unix 毫秒，日期参数为 `YYYY-MM-DD`，日期边界按北京时间计算。
- HTTP 错误通常返回 `{"error":{"code":"状态码","message":"错误说明"},"request_id":"..."}`；来源拒绝和数据库不可用响应可能没有 `request_id`。响应头 `X-Request-ID` 由中间件处理的正常响应提供。

## 身份与偏好

下表路径均相对于 `/api/v1`。

| 方法与路径 | 参数或请求体 | 行为 |
| --- | --- | --- |
| `GET /config` | 无 | 无需登录；返回钉钉企业 ID、演示开关、钉钉配置标记及环境。配置标记只检查 Client ID、Client Secret 非空 |
| `POST /auth/dingtalk` | `{"code":"一次性免登码"}` | 无需已有会话；验证平台身份，匹配预先创建且启用的用户，返回会话、用户和 CSRF token；普通用户还须具有可访问主体 |
| `POST /auth/demo` | `{"password":"本地演示密码","role":"admin"}` | 仅启用演示且非生产时可用，role 为 `admin` 或 `user`，默认 `admin`；同一客户端 IP 每分钟最多 10 次尝试 |
| `POST /auth/logout` | 空对象 | 需登录和 CSRF；立即撤销当前会话并清除 Cookie |
| `GET /me` | 无 | 返回姓名、头像、角色、上次主体、可访问主体和 CSRF token |
| `PATCH /me/preferences` | `{"last_tenant_id":1}` 或 `{"last_tenant_id":null}` | 保存有权限的主体，null 表示全部；需 CSRF |
| `GET /tenants` | 无 | 返回当前用户可访问的启用主体 ID 与名称 |

## 看板、明细与资料

`GET /dashboard` 和 `GET /events` 共用以下参数：

| 参数 | 默认与限制 |
| --- | --- |
| `tenant_id` | `all` 表示全部授权主体，也可填写单个主体 ID；指定无权访问主体返回 403 |
| `start_date`、`end_date` | 首尾日期均包含，范围 1～366 天；结束日期默认今天，开始日期默认向前取 7 天；只有完全不填两端日期时，看板趋势单独使用近 30 天 |

填写任一日期时，看板指标、排名、趋势及明细均使用补齐的同一范围。只填结束日期时向前补齐共 7 天；只填开始日期时结束日期为今天。日期倒置或范围超过 366 天返回 422。

`GET /dashboard` 返回四项 `cards`（当前值与上一等长周期的差值 `delta`）、逐日 `trend`、三类 Top 5 `tops`（新增员工、删除员工、主动退群群聊）、`unresolved_count`、`pending_jobs`、`range`、`metrics_range`、`trend_range` 和 `updated_at`。`unresolved_count` 为 group_change_unknown（其他/待核实）人数，按 quantity 求和，包含内部员工；已归类的 inferred 客户计入各业务指标且不重复计入此数；未完成任务包含所有非 done 任务，不受日期筛选限制。统计口径及平台边界见 [实现说明](实现说明.md)。

`GET /events` 另支持：

| 参数 | 含义 |
| --- | --- |
| `event_type` | `contact_added`、`contact_deleted`、`group_left`、`group_removed`、`group_change_unknown`；不填则全部 |
| `employee_id` | 员工外部 ID，精确匹配；跨主体筛选时同时传所属主体 ID |
| `employee_tenant_id` | 将筛选限制到员工所属主体，并校验当前用户权限 |
| `employee_keyword` | 员工姓名或ID包含匹配，最多100字符，去除首尾空格；匹配事件快照姓名、同主体员工资料姓名或员工ID，英文忽略大小写；与其他条件共同筛选 |
| `add_way` | 精确匹配添加方式；`unknown` 匹配 NULL 或官方编码0，`other` 匹配非 0～6 的非空值；两者不重叠 |
| `group_keyword` | 按有效展示群名包含匹配：历史快照优先，缺失时使用同主体当前群资料；最多 100 字符 |
| `limit` | 默认 20，范围 1～100 |
| `cursor` | 下一页使用`next_cursor`；返回已访问页使用该页`page_cursor`，最多4096字符 |

响应包含 `items`、`next_cursor`、`page_cursor`、`range`（服务端补齐的实际日期）、`total_records`（记录条数）、`total_quantity`（人数或关系变更人次）。按 `occurred_at DESC, id DESC` 排序，游标绑定用户、主体和筛选条件及首屏最大 ID；修改条件后须从首屏重新请求。`page_cursor` 也为第一页保存首屏最大 ID，返回第一页不会混入随后新入库的记录；首屏之后的新入库记录在刷新后显示。游标被篡改或条件不匹配返回 422。翻页须沿用首屏返回的实际日期区间，跨北京时间午夜也固定同一次浏览范围，刷新首屏才重新计算默认日期。

每次请求在同一条 SQL 中读取当页记录与整个筛选范围的总条数、总人数，空页也保留正确汇总；旧游标仍兼容，但其中携带的旧总数不再复用。最大 ID 只固定插入边界，已有记录被重试重分类、更新人数或删除后，后续请求会反映最新结果，因此页内容和总页数可能变化；跨页不是历史数据快照。重试新拆分且 ID 超过上界的记录在刷新首屏后显示。

新增、删除与群变更共用列表分页：桌面及手机均为上一页/下一页，始终显示页码、总记录条数和每页条数（10/20/50，默认20）。分页栏吸附视口底部；手机位于底部导航上方，内容保留占位以避免遮挡最后记录及页脚。筛选、每页条数变化或刷新从第一页重新查询。翻页失败保留当前页，可重新点击相应按钮。员工搜索输入提交后直接筛选新增/删除记录，指定员工下拉提供精确筛选；清空恢复当前日期和主体下的全部员工记录。

事件包含 ID、主体、事件类型、外部员工/客户/群/操作人 ID、删除方向、发生时间、添加方式、渠道 State、quantity、resolution、enrichment_status 和展示快照 snapshot。缺失字段可能为 null，不能用群主填充未知操作人。`resolution=inferred` 表示成员通过快照关联，符合外部客户分类条件时仍计入业务列表及统计。混合回调可拆为多个记录，本行 quantity 与 snapshot.reported_quantity（原平台总人数）分别展示；私有下划线字段不会经 API 返回。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /events/{event_id}` | 事件详情；不存在或不在授权范围返回 404 |
| `GET /employees` | 支持 `tenant_id`、`keyword`（姓名或ID，最多100字符）、`offset`（默认0）、`limit`（默认100，最大500）；资料与事件员工ID去重合并，缺资料以ID展示，按名称/主体/ID稳定排序；返回外部ID、主体ID和名称 |
| `GET /groups` | 支持 `tenant_id`、`keyword`（群资料名称包含匹配，最多 100 字符）、`offset`、`limit`，分页限制与员工候选相同；按名称/主体/外部 ID 排序，查询群资料快照，不合并事件群 ID |
| `GET /media/{media_id}` | 返回授权主体下的本地图片；不存在、越权或文件丢失返回 404 |

## 客户分析助手

以下路径相对于 `/api/v1`，均须登录；POST 另需 CSRF 及受信任 Origin。详见 [AI 助手使用与接入](AI助手使用与接入.md)。

| 方法与路径 | 参数或行为 |
| --- | --- |
| `GET /assistant/config` | 返回 enabled、model/rules 模式、模型名称及当前角色可用的 capabilities（id/name/description/example/admin_only）；不返回地址或密钥；无主体授权返回 403 |
| `POST /assistant/chat` | `{message, tenant_id?, start_date?, end_date?, event_id?, history?, query_type?, group_keyword?, group_offset?, group_limit?}`；message 去除首尾空白后须非空，最多 2000 字符；tenant_id 默认 all；event_id 为正整数；history 最多 6 条，每条最多 2000 字符，仅接受历史问题文本；query_type 为 auto（默认）或 groups，群关键词最多 100 字符，offset 为 0～1000000，limit 默认 20、范围 1～100 |

响应包括 `answer`、`mode`（model/rules）、`warning`、`range`、`previous_range`、四项 `cards`、`deletion_directions`、`unresolved_count`、可选 `rankings`、`sources`、`sources_label`、`event_id`、`event_explanation`（系统识别依据）、`event_occurred_at`、`updated_at` 和 `usage_tokens`。事件解释允许查询日期区间外的已授权事件，并提供实际事件时间。自然语言明确日期可覆盖页面日期，实际使用范围始终在响应中返回。

群列表提问自动识别，或通过 `query_type=groups` 显式选择（优先于事件上下文），返回 `result_type=groups`、`mode=rules`、`answer`、`groups` 和查询时间；不返回无关统计日期。`groups` 包含 items（群 id、name、tenant_id、tenant_name、synced_at）、total、offset、limit、keyword、has_more、next_offset、source=profiles 和 date_filtered=false。使用当前授权范围、与 `/groups` 相同的群资料筛选/稳定排序，不发起平台同步或模型调用；群列表不按事件日期筛选，群成员与群主资料不返回。翻页与筛选每次重新鉴权；没有资料时不宣称平台没有群。

完整数据工具可在同一 POST 中提交 `query`，并可提交上一条响应的 `context_query` 供「下一页」「这个群」等追问使用。query 优先于事件上下文与自动意图识别，格式示例：

```json
{"message":"查询员工资料","tenant_id":"all","query":{"capability":"employees","keyword":"示例","offset":0,"limit":20}}
```

`query.capability` 支持 capabilities、overview、tenants、tenant_settings、employees、customers、groups、group_detail、group_members、customer_followers、events、event_detail、statistics、trend、rankings、jobs、callbacks、users、audits、me、media。其余字段为 keyword（最多100）、entity_id（最多200）、entity_tenant_id（正整数）、offset（0～1000000）、limit（1～100）、start_date/end_date、event_type、deletion_direction、resolution、enrichment_status、employee_keyword/customer_keyword/group_keyword（各最多100）、employee_id/customer_id/group_id（各最多200）、add_way（最多20）、status（pending/running/retry/failed/done）、member_type（1内部员工/2外部联系人，仅用于群成员）、cursor（最多4096）。未知字段或能力返回422；不支持的能力/筛选组合返回422，不执行任意 SQL 或地址请求。

数据工具响应为 `result_type=data`、`mode=rules`，包含 `dataset` 和当前页 `query`。dataset 提供 title、columns（key/label）、items（白名单字段及可选 actions/event_id/media_id）、total、total_quantity、offset、limit、note、source、range、filters、page_query、next_query、previous_query。浏览器按返回的查询对象翻页或继续查看，不将原始资料发模型。事件查询的 cursor 签名绑定用户/主体/筛选并固定首屏 ID 上界；日期按响应实际区间沿用。

助手业务事件明细与 `/events` 共用同一次查询快照读取记录和汇总，采用相同的“固定新增 ID 边界、已有记录实时重算”规则；不将旧页总数作为后续页的依据。

资料类不按业务事件日期筛选。全局管理员能力、成员快照缺失、历史保留关系及任务错误脱敏等边界见 [完整能力清单](AI助手使用与接入.md)。即使客户端自行提交管理员能力，普通用户仍返回403；成员/跟进关系多候选时返回选择列表，不自动跨主体合并。同一请求完成查询后再次核对会话、角色与授权。

未启用返回 404，无效参数/日期返回 422，限流或并发占满返回 429，越权主体返回 403，越权/不存在事件返回 404。模型错误、超时或不完整输出返回 HTTP 200 的 rules 结果与非空 warning，不返回上游错误正文。生成后再次校验会话、角色和授权，变化时返回 401/403 并丢弃回答。统计绕过看板 TTL 缓存；响应不允许缓存。

## 管理接口

均需管理员会话，写操作须带 CSRF token。路径仍相对于 `/api/v1`。

| 方法与路径 | 请求或行为 |
| --- | --- |
| `GET /admin/tenants` | 全部主体及回调 URL、凭据非空标记；不返回密钥 |
| `POST /admin/tenants` | `{name, corp_id, credential_ref, enabled?}`；enabled 默认 true；返回新 ID，重复 CorpID 返回 409 |
| `PATCH /admin/tenants/{tenant_id}` | 必须提交 `{name, credential_ref, enabled}` 三项；不能修改 CorpID，成功后清空进程平台 token 缓存 |
| `GET /admin/users` | 用户 ID、姓名、钉钉 userid、角色、启用状态和授权主体 ID |
| `POST /admin/users` | `{ding_corp_id, ding_user_id, name}`；创建普通用户，返回 ID；重复身份返回 409 |
| `PUT /admin/users/{user_id}/tenants` | `{"tenant_ids":[1,2]}`，最多 1000 项；整体替换授权，空数组撤销全部；不存在的主体返回 422 |
| `GET /admin/jobs` | ID 倒序最近 100 项，包含主体、状态、尝试次数、最近错误、下次执行时间；无状态筛选或分页 |
| `POST /admin/jobs/{job_id}/retry` | 仅允许 retry、failed 任务，重置为 pending 并归零尝试次数；其他状态返回 409 |

主体名称、CorpID、用户姓名和平台身份字段长度均为 1～100。凭据引用须匹配 `^[A-Z][A-Z0-9_]{0,40}$`。新增主体不要求密钥已就绪；`credentials_ready` 仅表示三项凭据非空。角色提升、用户停用和用户删除没有对应管理接口；首位管理员通过 CLI 创建。

## 回调与健康检查

| 方法与绝对路径 | 行为 |
| --- | --- |
| `GET /callbacks/wecom/{callback_key}` | 企微挑战验证，验签解密后返回明文 echostr |
| `POST /callbacks/wecom/{callback_key}` | 接收加密 XML，验签、企业及字段校验，收件箱和任务提交成功后返回纯文本 success；报文最大 1 MiB |
| `GET /healthz` | 返回 `{"status":"ok"}`，只检查进程响应 |
| `GET /readyz` | 查询数据库；启用消费者时要求最近循环距今不超过 180 秒，成功返回 `{"status":"ready"}` |

回调无需业务登录 Cookie，使用平台签名鉴权。未知或停用主体为 404，缺少回调 Token/AESKey 为 503，校验失败为 400，报文超限为 413。健康检查通过不代表平台接口权限、真实回调或端到端业务已经验收。
