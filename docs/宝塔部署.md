# 宝塔部署（Linux + 主机 Nginx + Docker Compose）

使用 `compose.baota.yaml` 单独启动应用，宝塔 Nginx 负责域名和 HTTPS。前端在 Docker 构建时打包，由后端同源提供；SQLite 和媒体保存在 `app_data` 数据卷，无需 MySQL。启动脚本自动执行数据库迁移，并以单 worker 运行。

代码核对日期：2026-10-22。镜像构建使用 Node.js 24、pnpm 11.25.0、Python 3.12 和 uv 0.13.4；Python 运行依赖由 `pyproject.toml` 与 `uv.lock` 安装，前端使用 `frontend/pnpm-lock.yaml`。本指南已与配置核对，尚未执行服务器部署或 Docker 构建验收，当前本地验证见 [自测报告](自测报告.md)。

## 1. 准备服务器

在宝塔安装 Nginx、Docker 和 Docker Compose 插件。终端检查：

```bash
docker --version
docker compose version
```

将域名解析到服务器，安全组与防火墙放行 TCP 80、443。上传源码到 `/www/projects/wecom-monitor`，不要放进公开网站根目录；排除本地 `.env`、`.venv`、`node_modules`、`frontend/dist`、`data`、`backups` 和 `.git`。不要上传演示数据库。

以下命令均在服务器 Bash 终端执行。整份流程只使用 `compose.baota.yaml`，不与默认 `compose.yaml` 合并；默认配置会启动 Caddy，占用宝塔的 80、443 端口。端口 8000 只绑定本机，无需公网放行。本方案要求 Nginx 在主机运行；容器化 Nginx 的网络需要另行配置。

## 2. 创建正式配置并构建

```bash
cd /www/projects/wecom-monitor
# 仅首次执行；已有 .env 时请保留原配置和密钥。
cp -n deploy/baota.env.example .env
chmod 600 .env
docker compose -f compose.baota.yaml build
docker compose -f compose.baota.yaml run --rm --no-deps app python -m app.cli generate-keys
```

生成密钥的命令直接运行 CLI，不启动 Web 服务、不执行迁移。将输出的 `SECRET_KEY` 和 `PAYLOAD_KEY` 填入 `.env`，妥善保存；后续更新不能重新生成。构建会从镜像仓库、npm 和 PyPI 下载依赖，需保证服务器可访问这些源。

在宝塔文件编辑器中编辑 `.env`：

- `PUBLIC_ORIGIN` 改为实际 HTTPS 地址，例如 `https://monitor.example.com`，不加末尾 `/`。
- 保持 `APP_ENV=production`、`COOKIE_SECURE=true`、`DEMO_ENABLED=false`。
- 填入真实的钉钉内部 H5 应用参数和企微客户联系参数，详见 [配置指南](配置指南.md)。
- 示例凭据引用为 `ACME`。其他主体使用相应的 `WECOM_<REF>_*` 变量；新增或修改变量后需要重建应用容器。

`.env` 不提交仓库，也不通过网页公开。未配置钉钉时可以验证服务可达，但正式环境无法使用演示账号登录。

## 3. 启动与检查

```bash
docker compose -f compose.baota.yaml up -d
docker compose -f compose.baota.yaml ps
docker compose -f compose.baota.yaml logs --tail=100 app
curl --fail http://127.0.0.1:8000/readyz
```

首次启动执行迁移，需要等待启动完成后检查；正常返回 `{"status":"ready"}`。健康检查会持续检查数据库连接及后台任务状态；容器退出会自动重启，但 unhealthy 本身不会触发 Docker 自动重启。

首次创建管理员（替换为该企业的真实钉钉 userid，不是手机号或 AppKey）：

```bash
docker compose -f compose.baota.yaml exec app \
  python -m app.cli create-admin \
  --corp-id '真实钉钉企业ID' \
  --user-id '真实钉钉userid' \
  --name '管理员'
```

## 4. 宝塔域名、证书和反向代理

1. 宝塔「网站 → 添加站点」，绑定域名，选择纯静态，不创建数据库。站点目录使用与源码分开的空目录。
2. 在 SSL 中申请或上传证书，启用 HTTPS 和强制 HTTPS。
3. 添加反向代理：代理目录 `/`，目标 URL `http://127.0.0.1:8000`，发送域名 `$host`，关闭缓存。整个站点都转发，包括 `/api/`、`/callbacks/`、`/assets/` 和首页。
4. 如果手动编辑配置，将 [Nginx 片段](../deploy/baota.nginx.conf) 放入现有 HTTPS `server` 块，替换已有 `location /`。面板添加代理和手动片段二选一，避免重复 location。
5. 检查宝塔生成的静态文件正则 location：如果 JS、CSS、图片仍从空站点目录读取而出现 404，删除该站点这些默认静态匹配规则，使它们也经过应用代理。保留证书验证所需的 `/.well-known/` 配置。
6. 在宝塔检查配置并重载 Nginx，再验证：

```bash
curl --fail https://你的域名/readyz
```

浏览器打开首页。正式环境关闭 `/docs`，该路径不可用是预期行为。

## 5. 接入平台

钉钉应用首页配置为 `https://你的域名/`，配置安全域名、用户可见范围和接口权限，管理员从钉钉工作台进入。企微主体在管理页新增，凭据引用填 `ACME`，将管理页生成的回调 URL、相同 Token 和 EncodingAESKey 配置到企微后台；按平台要求设置服务器实际出口 IP。

管理员新增主体后，可以初始化资料快照（将 1 替换为实际主体 ID）：

```bash
docker compose -f compose.baota.yaml exec app python -m app.cli sync-profiles --tenant-id 1
```

快照同步不会导入历史事件。项目尚需完成真实企微与钉钉联调，部署成功后应验证登录、权限、URL 验证和实际业务回调，不能仅凭首页可访问认定业务验收完成。

## 6. 备份和更新

更新前使用项目的 SQLite 在线备份命令，避免直接复制正在写入的数据库。下面每次生成一个独立目录，并复制到服务器 `backups` 中：

```bash
cd /www/projects/wecom-monitor
backup_name="manual-$(date +%Y%m%d-%H%M%S)"
docker compose -f compose.baota.yaml exec app \
  python -m app.cli backup --output "/app/data/backups/$backup_name"
mkdir -p backups
docker compose -f compose.baota.yaml cp "app:/app/data/backups/$backup_name" ./backups/
```

确认命令成功并将备份复制到独立存储，同时另行安全备份 `.env`，其中原 `PAYLOAD_KEY` 是恢复加密数据所必需的。定期清理已转存的旧备份，避免数据卷持续增长。

保留 `.env`、部署目录及数据卷，上传更新后的源码，再执行：

```bash
docker compose -f compose.baota.yaml up -d --build
docker compose -f compose.baota.yaml ps
curl --fail http://127.0.0.1:8000/readyz
```

只修改 `.env` 时也需要 `up -d` 重新创建容器，单纯 `restart` 不会加载新的容器环境变量。不要执行 `down -v`，它会删除数据卷；不要更换 Compose 项目目录或项目名，否则可能关联到新的空卷。保持一个应用副本、一个 worker。

恢复时先停止应用，将备份的 `monitor.db` 和 `media` 恢复到原数据卷，处理旧 SQLite WAL/SHM 文件，并恢复原密钥及文件属主权限，再启动执行迁移。迁移后回退代码前应确认数据库兼容性。
