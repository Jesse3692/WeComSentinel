## 确定缺陷

### F1 P1 清空搜索触发退出后的新请求，迟到401使新会话失效

位置：frontend/src/App.vue:60、189–201。

复现：联系人页输入员工搜索词→主动退出→clearSession重置employeeKeyword→watch调用loadEmployees；该函数不检查me/退出状态，发出的请求已经属于invalidateSession之后的新代次。暂缓该请求，完成重新登录后返回401，API将其视为当前代次，expired清空新登录。浏览器已复现从重新登录的总览退回登录页。

建议：会话清理时禁止触发请求；loadEmployees必须检查登录状态与当前页面。新登录成功需要明确建立新的会话请求代次，并使退出阶段发出的请求失效；同时验证首次登录/me/偏好请求的先后关系，不能仅机械增加代次。

### F2 P2 保留旧头像后，群成员头像重试不再真正执行

位置：app/worker.py:242–245、328；任务重试上限位于93。

首次头像更新失败时，快照同时保存旧media_id和avatar_state=retry。下一次group_snapshot只判断缺姓名或缺media_id，因为两者都有，跳过get_profile；avatar_state仍为retry，normalize继续报错。即使平台或下载接口恢复也没有再次调用机会，可能耗尽5次任务重试。旧头像显示保留，但头像更新和任务状态无法恢复。

本地临时库复现两次group_snapshot：资料接口调用次数仍为1，第二次仍为retry。

建议将avatar_state=retry纳入重试条件，成功后转换状态；保留旧图片引用。增加“旧图存在→新图失败→重试恢复→任务done且事件数量/身份不变”的真实worker回归，而非只有首次无头像的场景。

### F3 P2 员工选项的旧错误污染新页面

位置：frontend/src/App.vue:147、189–199。

列表刷新现在不等待员工选项，切到总览后，旧员工请求失败；loadEmployees只校验employeeVersion和会话代次，没有校验页面/主查询版本，于是将错误写入总览全局error。浏览器已复现总览出现旧员工接口的simulated failure。

建议绑定页面/查询版本，离开使用员工筛选的页面后使请求失效，并将员工选项错误局限在对应筛选区域。该问题与旧分页错误不同，现有分页回归不会覆盖它。
