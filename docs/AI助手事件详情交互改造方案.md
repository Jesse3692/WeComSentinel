# AI 助手事件详情交互改造方案

日期：2026-10-26。

## 问题与目标

当前助手中的事件详情、事件依据均在 App.vue 中读取事件，随后显式关闭助手；请求失败也关闭助手。详情中的“让助手解释”会切换助手事件上下文，从而重置已有对话。手机助手层级为 110，现有详情遮罩层级为 100，单纯删除关闭语句会让详情被助手遮挡。

目标是完成“对话 → 查看详情 → 返回原对话 / 追加解释”的连续操作，保留已有消息、未发送输入和对话滚动位置，继续沿用事件详情接口的登录与主体鉴权。

## 交互约定

1. 点击助手事件入口时显示加载状态，读取成功后在助手上层打开现有详情内容；助手保持挂载和打开状态，暂时不可交互。
2. 电脑、平板复用详情弹窗；手机从助手进入时使用全屏详情，提供“返回助手”。关闭按钮、遮罩和 Esc 只关闭详情，并将焦点还给原事件入口。
3. 从普通业务列表进入详情，保留原有弹窗。助手未打开时，“让助手解释”仍打开事件上下文的新对话；已有助手对话时，在原对话追加明确指定主体和事件的解释，保留未发送输入。
4. 助手生成中禁用详情里的追加解释，避免取消正在处理的请求并立即触发单用户并发限制。
5. 加载失败在助手内显示错误和重试；404 不等于助手未启用。401 沿用会话清理，403 清理可能失效的对话内容。停止、关闭、切换上下文或退出登录后忽略迟到详情响应。

## 技术实现

- AssistantPanel.vue 管理事件详情请求、加载/错误/重试和取消，复用已有 API 客户端；成功时把已鉴权事件交给 App.vue 展示。
- App.vue 管理详情来源、弹窗焦点和展示；通过组件公开方法在已有对话中追加解释，不改变会触发清空的 scope。单次事件解释携带事件编号及所属主体，重试保留该请求参数。
- 助手在详情显示时设为 inert，并撤销其活动模态语义；详情层高于所有助手布局。详情关闭后恢复焦点，不重建对话 DOM。
- 抽取可重入的页面滚动锁，助手与详情分别持有释放函数；最后一个浮层关闭时才恢复原始 overflow，避免嵌套开关或断点切换导致锁泄漏。
- 不修改后端协议、数据库结构和事件业务分类；保留工作区已有后端修改。

## 实施结果
