# 群成员头像提前缓存与部署验证

日期：2026-10-23。用户明确要求部署；后续确认“稍后安排，先部署并同步现有群”，因此外部客户新入群后的真实离群验收暂不执行。

## 实现

- 新增Worker.sync_group，群资料同步、建群回调、update/add_member回调统一经过此入口。
- 先保存实际采集的群成员名单，再按成员类型和同主体成员ID预取资料及头像。群成员不在员工客户列表中，也会尝试按其真实ID补全；平台权限不足不会猜配身份或头像。
- 复用已有受限媒体下载器：仅腾讯白名单域名、HTTP升级HTTPS、不跟随重定向、大小与图片签名检查保持不变。
- 客户/员工Profile保留媒体引用，群成员快照额外保存media_id；退群/被移出时优先从历史资料与离群前成员快照取头像。即使成员Profile不可用，也可使用已有成员快照中的头像引用。
- 三个并发请求上限；单群预取80秒预算，保留部分进度。回调补全失败走现有任务有限重试，不创建新增联系人或流失事件。手动sync-profiles遇到不完整资料提示重新同步。
- 群快照保持采集时刻，不能用慢下载结束时间冒充成员采集时刻。条件更新防止较旧的同步结果覆盖更新的成员名单。
- 不修改事件分类、删除方向、人数、识别依据，不把群主当作操作人；头像缓存不等于身份被平台逐人确认。

## 回归范围

新增tests/test_group_avatar_prefetch.py覆盖：同步后离群、被移出复用历史头像；建群及进群回调预取但不创建业务事件；首次失败保留名单并重试恢复；成员快照头像在Profile缺失时仍可用且不串主体；慢下载不覆盖新快照；CLI sync-profiles包括仅在群中的客户；三并发上限及采集时刻保留。

此前头像URL限制、历史补全、会话及查询回归继续保留。

## 待安排的真实新事件验收

当前两个群没有外部客户，不能将本轮记为“真实客户已提前缓存并经离群验证”。用户选择稍后安排测试客户，需按以下顺序继续：

1. 让可获授权读取资料的测试客户入群，保持在群内。
2. 等建群/进群回调完成，或执行sync-profiles；确认该客户Profile和成员快照media_id已写入，对应文件存在、真实图片可解码。
3. 再让该客户退群或被移出，确认事件姓名/身份依据/人数和分类正确，列表与详情使用先前的媒体引用。
4. 测试期间不得用伪造回调、模拟头像或人工改分类来补验收。

平台在入群时就不允许读取的头像、下载始终失败的头像，以及从未缓存过的历史照片，不能承诺事后恢复；失败与未提供状态应保留。群同步缓存只减少未来离群后的资料不可访问风险，不绕过平台权限。
