## 2. 企业微信接口清单

请求前缀：`https://qyapi.weixin.qq.com/cgi-bin/`。

除获取 token 外，以下接口都通过查询参数携带 `access_token`。表中仅列项目当前使用的参数和返回字段，不是平台完整字段定义。

| 接口 | 方法及路径 | 当前请求与使用结果 | 调用场景 | 官方来源 |
| --- | --- | --- | --- | --- |
| 获取 access_token | `GET /gettoken` | 参数 `corpid`、`corpsecret`；读取 `access_token`、`expires_in` | 业务接口调用前取得凭证 | [获取 access_token](https://developer.work.weixin.qq.com/document/path/91039) |
| 读取成员 | `GET /user/get` | 参数 `userid`；使用姓名、头像等资料 | 回调处理、手动资料同步 | [读取成员](https://developer.work.weixin.qq.com/document/path/90196) |
| 获取客户详情 | `GET /externalcontact/get` | 参数 `external_userid`；读取 `external_contact`、`follow_user` | 客户资料补全、获取跟进关系中的添加方式 | [获取客户详情](https://developer.work.weixin.qq.com/document/path/92114) |
| 获取客户群详情 | `POST /externalcontact/groupchat/get` | JSON：`chat_id`、`need_name=1`；读取 `group_chat` | 群回调处理、群资料快照同步 | [获取客户群详情](https://developer.work.weixin.qq.com/document/path/92122) |
| 获取客户联系成员列表 | `GET /externalcontact/get_follow_user_list` | 读取 `follow_user` | 手动同步入口、检测客户联系权限 | [获取配置了客户联系功能的成员列表](https://developer.work.weixin.qq.com/document/path/92571) |
| 获取客户列表 | `GET /externalcontact/list` | 参数 `userid`；读取 `external_userid` 列表 | 按员工枚举客户，再逐个补全资料 | [获取客户列表](https://developer.work.weixin.qq.com/document/path/92113) |
| 获取客户群列表 | `POST /externalcontact/groupchat/list` | 同步请求 JSON：`limit=100`、`cursor`；读取 `group_chat_list`、`next_cursor` | 手动分页同步；检测脚本使用 `limit=1` | [获取客户群列表](https://developer.work.weixin.qq.com/document/path/92120) |

### 2.1 token 与请求处理

- token 在进程内按主体 ID 和凭据引用隔离缓存，根据平台返回有效期提前 120 秒过期；进程重启后重新获取。
- 业务请求返回 `40014` 或 `42001` 时，清除对应 token，重新获取并重试一次。
- HTTP 客户端超时为 10 秒，禁止自动跟随重定向。
- 平台异常转换为不含密钥 URL 的错误信息，例如 `platform_error_错误码`。
- 当前每个企微主体只有一套 Secret，成员资料接口与客户联系接口共用这套凭据，需要逐个验证权限。

### 2.2 资料补全与同步边界

- 员工、客户资料使用约 5 分钟缓存；新增联系人和客户编辑事件会强制刷新客户资料，新增关系未取得添加方式时保留待补全。
- 客户删除关系后可能无法再查询详情。已有快照时优先保留快照，没有资料时保留事件及资料不完整状态。
- 头像通过资料返回的 URL 下载保存，不是另外调用“获取临时素材”接口。
- `sync-profiles` 同步当前员工、客户和客户群资料，不补录历史添加、删除、退群事件，也不是已实现的定时全量同步。
- 群同步、建群和成员进群先保存成员快照，再预取头像（最多 3 个并发、单群 80 秒预算）。离群后优先复用同主体历史媒体，不能按昵称跨 ID 补图。
- 当前添加方式 0 和缺失值均显示/筛选为未知来源，“其他”排除 0～6；真实 0 编码样本的修复与客户端复验见 [真实验收记录](真实钉钉环境验收记录.md)。
- 当前客户详情调用没有继续处理跟进成员分页，不能认定已经取得全部跟进关系。

## 3. 企业微信回调

### 3.1 回调地址与请求处理

本系统的接收地址为：

```text
https://你的应用域名/callbacks/wecom/{callback_key}
```

`callback_key` 由系统创建主体时生成，从管理页复制完整 URL。该路径属于本项目，不是企业微信官方 API 路径。

| 请求 | 参数或报文 | 本系统处理 |
| --- | --- | --- |
| `GET` URL 验证 | `msg_signature`、`timestamp`、`nonce`、`echostr` | 验签、解密并校验接收企业，返回明文挑战值 |
| `POST` 事件推送 | 查询参数含签名、时间戳、随机串；XML 含 `Encrypt` | 验签解密、核对企业与必要字段、持久化入队，返回 `success` |

签名使用 Token、timestamp、nonce、密文排序后计算 SHA-1。解密使用 EncodingAESKey 对应的 AES 密钥，同时验证密文接收企业和 XML 中的 `ToUserName`。未知或停用主体返回 404；缺少回调凭据返回 503；校验失败返回 400。

官方来源：[接收消息与事件](https://developer.work.weixin.qq.com/document/path/90930)、[客户联系回调概述](https://developer.work.weixin.qq.com/document/path/92116)。

### 3.2 当前处理的事件

| Event | ChangeType / 其他字段 | 业务处理 |
| --- | --- | --- |
| `change_external_contact` | `add_external_contact` | 新增客户关系，补全员工和客户资料 |
| `change_external_contact` | `del_external_contact` | 员工删除客户，记录 `employee_deleted_customer` |
| `change_external_contact` | `del_follow_user` | 客户删除员工，记录 `customer_deleted_employee` |
| `change_external_contact` | `edit_external_contact` | 刷新客户资料，不新增流失记录 |
| `change_external_chat` | 群变化事件 | 查询并更新群快照 |
| `change_external_chat` | `UpdateDetail=del_member` | 保存人数和原因；证据充分的外部客户按主动退群/被移出分类，其余进入其他/待核实 |

官方来源：[客户联系事件格式](https://developer.work.weixin.qq.com/document/path/92130)。

### 3.3 群退群与被踢的能力边界

代码将 `QuitScene=0` 映射为平台报告的主动退出，`QuitScene=1` 映射为平台报告的被移出，并读取 `MemChangeCnt`。有效快照证据识别出的外部客户按原因保存为 `group_left` 或 `group_removed`，识别依据为 `inferred`；其余记录保留 `group_change_unknown`。

回调没有逐人成员字段时，系统用有效的前后成员快照和已缓存资料关联身份。外部客户按业务分类展示并计入统计，识别依据仍标为系统推断。内部成员、证据不足或未知原因不计入外部客户流失；没有操作人不妨碍已关联客户归类，也不会用群主猜测操作人。详细条件见 [客户事件分类与识别依据](群成员识别状态.md)。

`MemChangeList/Item` 为完整文本 ID 列表时，解析器保留 ID 并与快照差异的数量、唯一性和成员集合交叉核对；冲突标记 `callback_snapshot_conflict`。旧 `[{}]` 不当作有效 ID，不仅靠姓名或照片把不同平台 ID 合并。

已有真实受控退群/移出及历史头像通过记录；复杂并发、新客户冷缓存和可靠操作人仍须单独验收，不能扩大既有样本结论。

### 3.4 四类业务事件的文档定位

查看企业微信开放平台的“客户联系 → 事件回调 → 事件格式”。这里讨论的是外部客户关系和客户群，不是企业内部通讯录成员的添加、删除事件。

- [客户联系事件格式（92130）](https://developer.work.weixin.qq.com/document/path/92130)：查找下表的事件名称，阅读回调 XML 和字段说明。
- [接收事件服务器（92129）](https://developer.work.weixin.qq.com/document/path/92129)：查阅事件接收配置入口，与本文 3.1 节的本项目回调地址配合使用。

| 需求中的业务事件 | 在事件格式文档中搜索 | 识别条件 |
| --- | --- | --- |
| 新增联系人 | 添加企业客户事件 | `Event=change_external_contact`，`ChangeType=add_external_contact` |
| 删除联系人：员工删除客户 | 删除企业客户事件 | `Event=change_external_contact`，`ChangeType=del_external_contact` |
| 删除联系人：客户删除员工 | 删除跟进成员事件 | `Event=change_external_contact`，`ChangeType=del_follow_user` |
| 主动退群 | 客户群变更事件 | `Event=change_external_chat`，`ChangeType=update`，`UpdateDetail=del_member`，`QuitScene=0` |
| 被踢出群 | 客户群变更事件 | `Event=change_external_chat`，`ChangeType=update`，`UpdateDetail=del_member`，`QuitScene=1` |

四类业务需求不等于四种独立回调：“删除联系人”有两个方向；“退群”和“被踢”共用客户群变更回调，通过退出原因区分。如果要统计客户主动流失，客户删除员工应与员工删除客户分开统计。

表中字段映射与当前项目的处理约定对应；本次整理未能读取官方最新正文，实际支持字段、推送条件和权限要求仍需对照官方页面及真实回调样本核验。不能把上述映射当成真实平台联调已经通过。

### 3.5 四类事件需要向公司确认的问题

1. “删除联系人”包含员工删除客户、客户删除员工，还是只统计客户主动删除员工？同一客户与不同员工的关系如何计数？
2. “退群”和“被踢”只统计外部客户，还是包含内部员工？如果回调只能确认退出人数，是否允许展示“成员待核实”，并与已确认指标分开？
3. 群事件是否必须展示具体离群成员和踢人操作人？若必须，需提供可获取这些字段的数据来源及真实样本，不能用群主代替操作人。
4. 是否有可用于联调的测试员工、外部客户和客户群？由公司指定人员执行新增、双向删除、主动退群和移出成员操作，核对回调、入库记录和页面结果。
5. 验收按关系变化次数、去重客户数还是群成员退出人数统计？应明确时间范围、主体隔离及重复回调的去重口径。

## 4. 企业微信配置

### 4.1 主体与凭据的对应关系

```text
数据库主体：corp_id + credential_ref=ACME
    → WECOM_ACME_SECRET
    → WECOM_ACME_TOKEN
    → WECOM_ACME_AES_KEY
```

| 配置 | 配置位置 | 含义 |
| --- | --- | --- |
| `corp_id` | 本系统主体管理页，保存到数据库 | 企微企业 ID，运行时用于获取 token 和校验回调 |
| `credential_ref` | 主体管理页，例如 `ACME` | 项目自定义的凭据引用，用于匹配环境变量名称 |
| `WECOM_ACME_SECRET` | 服务器环境变量或 `.env` | 与该企业、所需接口权限对应的 Secret |
| `WECOM_ACME_TOKEN` | 环境变量或 `.env`；企微回调配置页 | 回调验签 Token，两处必须一致；不是 API access_token |
| `WECOM_ACME_AES_KEY` | 环境变量或 `.env`；企微回调配置页 | EncodingAESKey，两处必须一致；43 字符编码值，可解码为 32 字节密钥 |
| `WECOM_ACME_CORP_ID` | 环境变量或 `.env`，可选 | 检测脚本使用；不能代替运行时数据库主体配置 |
| `callback_key` | 系统自动生成 | 识别回调所属主体 |
| `enabled` | 主体管理页 | 主体启用状态 |

环境变量优先于 `.env`。其他企业使用不同凭据引用，例如 `BETA` 对应 `WECOM_BETA_*`。

配置示例：

```dotenv
WECOM_ACME_SECRET=具有所需接口权限的Secret
WECOM_ACME_TOKEN=与企微后台一致的回调Token
WECOM_ACME_AES_KEY=企微后台生成的EncodingAESKey
# 可选，仅供检测脚本使用
WECOM_ACME_CORP_ID=企业微信CorpID
```

### 4.2 平台后台配置步骤

1. 在[企业微信管理后台](https://work.weixin.qq.com/)确认企业，取得 CorpID。
2. 配置客户联系使用范围、应用可见范围和客户群相关权限。
3. 取得能调用本项目接口的 Secret，逐个核对成员、客户和群接口权限。
4. 按后台要求填写服务器实际出口可信 IP。
5. 在本系统新增主体，填写名称、CorpID 和凭据引用，复制回调 URL。
6. 在对应接收事件服务器配置中填写 URL、Token、EncodingAESKey，保存并通过 URL 验证。
7. 使用测试员工、客户和测试群验证真实事件、任务处理与业务明细。

公网 HTTPS 是本项目生产部署要求。本地 `localhost` 地址不能作为企微服务器可访问的生产回调地址。获取 access_token 成功不代表客户联系、成员资料和群权限全部通过。

## 5. 钉钉接口与登录流程

### 5.1 实际调用接口

| 接口 | 方法及地址 | 当前参数和返回字段 | 官方来源 |
| --- | --- | --- | --- |
| 获取客户端免登码 | `dd.runtime.permission.requestAuthCode` | 传 `corpId`，取得 `code` | [钉钉官方 H5 免登示例](https://github.com/open-dingtalk/h5app-auth-demo) |
| 获取内部应用 token | `POST https://api.dingtalk.com/v1.0/oauth2/accessToken` | JSON：`appKey`、`appSecret`；读取 `accessToken`、`expireIn` | [获取企业内部应用 accessToken](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app) |
| 通过免登码获取用户信息 | `POST https://oapi.dingtalk.com/topapi/v2/user/getuserinfo` | 查询参数 `access_token`；JSON：`code`；读取 `result.userid` | [通过免登码获取用户信息](https://open.dingtalk.com/document/development/obtain-the-userid-of-a-user-by-using-the-log-free) |
| 查询用户详情 | `POST https://oapi.dingtalk.com/topapi/v2/user/get` | 查询参数 `access_token`；JSON：`userid`；使用 `result.name`、`result.avatar` | [查询用户详情](https://open.dingtalk.com/document/development/query-user-details) |

前端动态加载 `dingtalk-jsapi`，在 `dd.ready` 后请求免登码，等待超时设置为 12 秒。

注意 JSAPI 版本区别：当前项目调用 `dd.runtime.permission.requestAuthCode({corpId})`；官方新的 [`dd.requestAuthCode` 示例](https://open.dingtalk.com/tools/explorer/jsapi?id=11723)要求 `clientId` 和 `corpId`。迁移时应同时核对 SDK、参数和客户端支持情况，不能直接混用。

### 5.2 登录及本系统授权

```text
用户从钉钉工作台打开 H5
→ 前端取得临时 code
→ POST /api/v1/auth/dingtalk，提交 {code}
→ 服务端获取应用 accessToken
→ code 换取 userid
→ 查询姓名、头像
→ 按配置的钉钉企业 ID + 平台返回 userid 查询本系统用户
→ 校验用户启用状态、角色和主体授权
→ 设置 2 小时本系统登录会话
```

`/api/v1/auth/dingtalk` 是本项目接口。系统不接受前端自行提交 userid 作为身份依据，不会因平台身份有效就自动注册用户或授予权限。

管理员应提前通过 `create-admin` 初始化；其他用户由管理员创建并分配主体权限。用户不存在、已停用，或普通用户没有可访问主体时，返回 403。

本系统登录 Cookie 为 `monitor_session`，设置 HttpOnly、SameSite=Lax；是否设置 Secure 由 `COOKIE_SECURE` 控制。平台 accessToken 与本系统会话是不同凭证。

### 5.3 token 实现说明

钉钉应用 token 缓存在进程内，按平台有效期提前 120 秒过期。当前没有实现企微适配层那样的失效错误触发刷新并重试。后端返回的企业标识取自 `DING_CORP_ID` 配置，应确保 CorpID、AppKey 和 AppSecret 属于同一企业内部应用。

## 6. 钉钉配置

| 配置 | 含义 | 项目用途 |
| --- | --- | --- |
| `DING_CORP_ID` | 钉钉企业 ID | 前端取得免登码、后端匹配企业内用户 |
| `DING_CLIENT_ID` | 内部应用 Client ID / AppKey | 请求 token 时作为 `appKey` |
| `DING_CLIENT_SECRET` | 内部应用 Client Secret / AppSecret | 请求 token 时作为 `appSecret` |
| `DING_AGENT_ID` | 应用 AgentID | 保留配置并供检测脚本检查，当前登录调用未使用 |
| 应用首页、PC 首页 | H5 部署地址 | 用户从工作台打开应用 |
| 应用可见范围 | 允许使用应用的员工范围 | 确保测试或正式用户可以进入应用 |
| 接口权限、安全配置 | 用户信息权限、域名/IP 等 | 按当前平台后台要求配置 |

```dotenv
DING_CORP_ID=钉钉企业ID
DING_CLIENT_ID=内部应用AppKey
DING_CLIENT_SECRET=内部应用AppSecret
DING_AGENT_ID=内部应用AgentID
```

配置步骤：

1. 在[钉钉开放平台](https://open.dingtalk.com/)创建或选择目标企业的内部 H5 应用。
2. 获取同一应用对应的 CorpID、Client ID、Client Secret 和 AgentID。
3. 开通当前调用的免登用户信息、用户详情相关权限，配置可见范围。
4. 将首页和 PC 首页指向本项目部署地址，按后台要求配置域名与安全项。
5. 写入服务器配置，重启服务，初始化真实管理员。
6. 从工作台测试免登、用户授权、退出和会话过期，再分别验证 PC、iOS、Android 客户端。

钉钉 CorpID、企微 CorpID、AppKey、AgentID、UserID 是不同字段，不可混填。当前未实现钉钉机器人消息、审批、群消息发送或钉钉事件回调。

## 7. 公共运行配置

| 配置 | 用途 / 要求 |
| --- | --- |
| `PUBLIC_ORIGIN` | 公网访问地址，也是生成企微回调 URL 的前缀 |
| `APP_ENV=production` | 开启生产配置校验 |
| `COOKIE_SECURE=true` | Cookie 仅通过 HTTPS 发送 |
| `DEMO_ENABLED=false` | 生产环境必须关闭演示登录 |
| `SECRET_KEY` | 本系统签名密钥，至少 32 字符；不是平台 Secret |
| `PAYLOAD_KEY` | 本系统回调载荷存储加密的 Fernet 密钥；不是 EncodingAESKey |
| `WORKER_ENABLED=true` | 启用后台消费者，处理已入库回调并补全资料 |
| `DATABASE_URL` | 保存主体、用户授权、事件、任务和资料快照 |
| `MEDIA_DIR` | 保存下载的头像文件 |

生产配置示例：

```dotenv
APP_ENV=production
PUBLIC_ORIGIN=https://你的应用域名
COOKIE_SECURE=true
DEMO_ENABLED=false
WORKER_ENABLED=true
```

平台凭据和本系统密钥各有用途，不能互相替代。真实值填写到部署环境或 `.env`，本文只提供名称和占位示例。

## 8. 检测、初始化与同步命令

在项目根目录执行以下 PowerShell 命令，替换示例企业 ID、用户 ID 和主体 ID。

```powershell
# 企业微信：本地格式和加解密检测，不访问平台
uv run python -m scripts.check_wecom --ref ACME --corp-id 企业微信CorpID --offline

# 企业微信：在线凭据、客户联系成员列表和客户群列表权限检查
uv run python -m scripts.check_wecom --ref ACME --corp-id 企业微信CorpID

# 企业微信：额外验证给定地址的 GET 挑战响应
uv run python -m scripts.check_wecom --ref ACME --corp-id 企业微信CorpID --callback-url "https://你的应用域名/callbacks/wecom/实际标识"

# 钉钉：检查应用凭据
uv run python -m scripts.check_dingtalk

# 钉钉：按提示隐藏输入新获取的一次性 code，会消费该 code
uv run python -m scripts.check_dingtalk --with-login

# 创建本系统真实管理员，会写入数据库
uv run python -m app.cli create-admin --corp-id 钉钉CorpID --user-id 钉钉UserID --name 管理员姓名

# 同步指定主体的当前资料快照，会调用平台并写入本地资料
uv run python -m app.cli sync-profiles --tenant-id 1
```

检测脚本的退出码 0 仅说明已执行项目通过，仍需查看 `skip` 项。一次 token 获取成功不代表完整免登或业务权限通过；本机发起的回调 GET 检查成功也不证明企微服务器可访问该地址。
