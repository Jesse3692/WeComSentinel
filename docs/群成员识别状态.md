# 群成员识别状态

群回调的变更原因、成员识别依据和资料完整度分别展示。缺少操作人不会让已完成的成员快照比对降为未知。

- 平台逐人确认：显示“已识别”。
- 已保存的 `member_evidence=snapshot_difference`，候选数等于报告人数且保留成员标识或有效姓名：标题直接显示“主动退群”或“被移出群”，数据状态显示“已识别”；识别依据单独说明成员列表比对属于系统推断。主信息展示成员姓名，姓名缺失展示标识。成员类型未知只影响类型展示，不推翻已有身份比对。
- 缺少变更前快照、差异人数不一致或同时有新增成员：仍待核实，并给出具体原因。不会无条件显示“具体成员尚未确认”。

快照关联是一种推断，不等于平台逐人确认；多个变更可能发生在两次取群资料之间。因此不将这类记录自动改为 `resolution=exact`，也不自动加入已确认客户流失统计。内部员工不计入客户流失。两类记录仍保存在原分类中，对应页签更名为“快照识别 / 待核实”。

这是展示层修复，服务器已有快照证据的历史记录无需重放回调或重建数据库，部署新前端后即可展示。只有姓名缺失时显示“姓名未提供”，不会将姓名缺失等同于没有比对结果。

本地验证：`node scripts/test-group-evidence.cjs`，以及 `pnpm --dir frontend run build`。这些检查不代表真实平台回调联调完成。

## 2026-10-22 判定检查与修复

| 输入事件 | 当前判定 | 证据不足时的处理 |
| --- | --- | --- |
| add_external_contact | 新增联系人，回调中的员工/客户 ID 确认身份 | 姓名获取失败保留 ID，任务重试资料补全；缺 ID 则任务报错，不创建假“已识别”事件 |
| del_external_contact | 员工删除客户 | 使用相同主体历史资料及 ID；不把删除方向倒置 |
| del_follow_user | 客户删除员工 | 使用相同主体历史资料及 ID |
| edit_external_contact | 刷新客户资料，不新增流失事件 | 刷新失败进入重试 |
| add_half_external_contact / transfer_fail / subscribe | 不计入完整关系新增、删除或退群统计 | 保留原始 Inbox；本次未扩大业务统计口径 |
| change_external_chat / update / del_member，QuitScene=0 | 平台报告主动退群 | 成员归属由快照证据单独判断 |
| 同上，QuitScene=1 | 平台报告被移出群 | 群主不冒充操作人 |
| 同上，退出原因缺失或未知 | 群成员减少，退出方式未提供 | 不默认认定主动退群或被踢 |
| create / add_member / change_owner / change_name / change_notice | 刷新群资料和成员快照 | 不生成退群事件 |
| dismiss / 未支持事件 | 不生成个人退群事件 | 不把整群解散转换成逐人退群 |

修复的后端问题：

1. 首次群接口失败或短暂返回旧成员列表时，持久保存本次回调原始的变更前快照，供重试比对；不会用事件后的缓存替换原基准。已有比对结果在重试中保留。
2. 成员候选保留 ID，支持成员类型的数字和字符串表示；已有群内姓名或同主体缓存优先使用，姓名缺失按 ID 调用资料接口补全。
3. 头像保存异常不再导致已获取的姓名被丢弃。身份是否已识别、资料是否完整分开处理。
4. 群人数非法或缺失不默认编造 1 人；缺少 ChatId 不生成无所属群的事件。诊断脚本输出对应的固定错误码。
5. 群名、候选姓名及类型已完整时显示资料齐全；操作人缺失不阻止资料状态判定。

变更前基准保存在事件内部字段 `_before_members`，列表和详情 API 均不返回该内部字段。每个回调只生成一条群事件，重试不增加统计数量。

历史限制：旧记录若已存快照候选，更新前端即可展示；旧记录没有保存成员 ID 或变更前快照时，不能用今天的群列表捏造过去退出的人。新后端的基准保留机制对更新后首次处理的回调生效。历史失败任务可在管理页重试，但不保证恢复此前未保存的证据。

验证证据位于 `tests/test_event_judgment.py`、`tests/test_system.py`、`scripts/test-group-evidence.cjs`，覆盖分类方向、未知原因、缺字段、同主体隔离、重试恢复、重放去重及前端身份回退。协议映射沿用项目现有定义；本次尝试访问企业微信官方 92129/92130 文档未成功，未据非官方资料新增字段或声称完成最新协议全面校验。

## 展示简化

事件标题和变更类型仅表达业务动作，不再追加“快照比对识别”。成员详情标题为“成员资料”，比对依据集中在“识别依据”字段。已识别记录的底部保留一行普通统计说明，取消重复的大段警告；无证据的记录仍显示“成员待核实”及具体原因。该调整不改变数据库事件分类、确认等级或统计口径。
