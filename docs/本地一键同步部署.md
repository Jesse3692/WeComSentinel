# 本地一键同步部署

代码核对日期：2026-10-24，依据 `deploy/sync.ps1` 和 `deploy/update.py`。已有实际源码同步发布及公网核对记录，见 [带鱼屏版本部署与验证](带鱼屏自适应优化与验证.md)。本轮只核对文档，未执行构建、打包或连接服务器。

在 Windows 项目目录运行 PowerShell 脚本，本地构建前端，经 SSH/SCP 上传源码和构建产物，再在 Linux 服务器上备份、更新依赖、迁移数据库、重启和检查 `/readyz`。无需 Git 提交、推送或服务器拉取，当前工作目录中的代码改动也会上传。

## 首次配置

本地需要 PowerShell、Node.js、pnpm 和 Windows OpenSSH 客户端（`ssh`、`scp`），无需本地 Python。`sync.ps1` 直接执行构建、ZIP 打包和 SSH 上传；服务器侧使用已有 Python 环境运行随包携带的重启辅助脚本。服务器需要已有的 `.env`、`.venv/bin/python` 和 `uv`；无需 Node.js、pnpm 或 Docker。uv 可位于服务器用户的 `~/.local/bin` 或 PATH 中。

```powershell
Copy-Item deploy/sync.example.json deploy/sync.local.json
notepad deploy/sync.local.json
```

填写服务器 IP（或 SSH 配置别名）及实际目录：

```json
{
  "host": "服务器IP",
  "user": "root",
  "ssh_port": 22,
  "remote_dir": "/root/workspace/wecom-monitor",
  "identity_file": "",
  "service": "",
  "app_port": 8000,
  "timeout": 90
}
```

- `remote_dir` 必须是服务器上已有项目的绝对路径，用 `pwd` 确认；当前脚本要求路径不含空格。
- `identity_file` 可填本地私钥路径，例如 `C:/Users/Administrator/.ssh/id_ed25519`。留空使用 SSH 默认配置，可交互输入密码；脚本多次连接可能多次询问密码。
- 当前使用 `nohup` 或 `uv run uvicorn ... &` 时，`service` 留空。脚本仅停止工作目录等于项目目录、运行 `app.main:app` 的 Uvicorn，随后独立后台启动单 worker，追加日志到 `uvicorn.log`。
- 已安装 systemd 服务时填写 `wecom-monitor`，SSH 用户必须具有管理该服务及写入项目目录的权限，服务的 WorkingDirectory 必须匹配。宝塔 Supervisor 管理的进程不适用留空模式，需先切换到 systemd 或普通后台启动。
- `sync.local.json` 已被 Git 忽略。

## 日常更新：本地一条命令

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\sync.ps1
```

脚本依次执行本地 pnpm 安装及构建、白名单打包、上传、服务器数据库/媒体/`.env` 备份、停止服务、备份并替换旧代码、`uv sync --locked --no-dev --python <原环境基础解释器> --no-python-downloads`、Alembic 迁移、启动服务和轮询本机 `/readyz`。环境备份权限设为 600；检查 HTTP 200 且 JSON `status=ready` 后才报告成功。迁移包含历史群客户分类，不会因仅上传新界面而自动完成，须完整执行更新流程。

源码上传范围为 `app/`、`migrations/`、`scripts/`、`frontend/dist/`、`pyproject.toml`、`uv.lock`、`alembic.ini`、`.python-version`；服务端辅助脚本随包上传。服务器 `.env`、`.venv`、`data` 和原有日志保留。替换整个代码目录可移除旧版本已删除的模块和前端文件。

只在本地构建并检查发布包，不连接服务器：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\sync.ps1 -BuildOnly
```

本地包在 `.deploy/<发布编号>/release.zip`；服务器上传内容在 `.deploy/releases/`，备份在 `backups/deploy-*`，旧代码位于备份中的 `code/`。这些目录会保留，确认稳定后自行清理旧版本。

## 失败处理和验证范围

构建或上传失败不会停止原服务。服务器更新阶段出现错误会返回非零退出码，可能留下已停止的服务；脚本不自动回滚数据库。根据输出修复问题后重新运行同步命令。数据库迁移后回滚需要同时考虑数据库与旧代码兼容性。

就绪检查发生在服务器配置端口（默认 `127.0.0.1:8000`），不证明域名、Nginx、钉钉登录或企微业务回调通过。已有本地发布包排除运行数据、旧代码备份替换、保留服务器数据及 SSH 命令生成的验证记录，也已有真实 SSH 发布记录；每次发布仍需独立核对公网资源及业务。源码发布成功不能代替生产 HTTPS 跳转、Secure Cookie、演示数据隔离和平台权限验收，当前缺口见 [未完成项复查](需求1-8章当前未完成项复查.md)。
