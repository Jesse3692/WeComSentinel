# 当前界面对照需求第1–8章复查

> 后续状态：本报告记录的3项缺陷和2处文案问题已修复；当前结果以《界面五项修复与部署验证》为准，下文保留修复前的复现证据。

日期：2026-10-23。基于当前工作区及已构建前端，对照 `docs/requirement/研发试岗项目-企微用户流失监控.md` 第1–8章。本轮不修改产品代码、不部署、不改线上数据。浏览器检查使用本地构建和模拟接口，不等于真实钉钉验收。

## 确定的问题

### U1 P2 排名长名称导致横向溢出

`frontend/src/style.css` 的 `.rank-name` 没有长连续文本换行或截断保护。后端排名允许以员工/群 ID 兜底名称，因此不是只可能出现中文姓名。

本地给排名提供超长连续英文员工标识，在1440、900、375、390、428px均复现页面横向溢出；375px下排名卡片被撑到约千像素。普通短名称检查通过，不能据此断言长文本适配通过。

证据：`artifacts/ui-audit/inspect.cjs`，截图 `artifacts/ui-audit/dashboard-375.png`。应对排名名称、主体名称及容器统一补长文本处理，并保留完整内容的查看方式。

### U2 P2 趋势图跨年提示丢失年份

`frontend/src/App.vue:116` 将传给横轴的数据直接裁成 `MM-DD`，默认tooltip也继承短日期。跨年/最长366天范围时，仅看悬浮提示无法确认所属年份，同月日还可能在两端重复。

本地模拟2025-10-23至2026-10-23，悬浮提示实际为 `10-24`。应保留完整ISO日期作为图表数据，仅将轴标签格式化为短日期，tooltip显示完整年月日。

证据：`artifacts/ui-audit/interactions.cjs`。这不表示后端范围计算错误；问题在显示。

### U3 P2 个人中心刷新按钮没有刷新资料

所有页面均展示“刷新数据”，但 `refresh()` 没有 `me` 分支。进入“我的”并点击刷新后，`/me` 请求次数仍为1，用户姓名、头像及授权主体信息没有重新读取。

应让该按钮实际更新访问上下文，或在该页取消无作用的刷新入口。证据同上。

## 确定的文案差异与歧义（不是业务算法缺陷）

- 汇总导航已正确，但页面标题仍为“客户关系总览”、页脚仍写“每30秒更新总览”。如果要统一页面名称，应同步改为“客户关系汇总”及“更新汇总”；需求并未要求所有标题必须与短Tab完全相同，因此属于一致性收尾。
- 新增排名标题是“新增员工 TOP 5”，容易理解成新入职员工，需求含义是添加客户最多的员工。建议“新增客户员工 TOP 5”或“客户新增 Top 5 员工”。现有“删除关系员工”保留双向关系统计含义，不能仅为名称一致擅自改变口径。

## 真实钉钉及平台环境验收

1. iOS、Android及PC免登、未授权提示、两小时会话过期自动重登、主动退出后重开；正常进入、返回、切后台再恢复。
2. 真机375–428px、安全区、原生日期选择器、软键盘、横竖屏、下拉刷新和触底分页、弹窗滚动与返回操作。普通Edge模拟宽度不代表这些通过。
3. 真实客户进群前已缓存照片，随后主动退群/被移出仍能加载原头像；当前用户头像及有授权员工头像实际显示。历史无缓存且平台不再提供的头像不能凭昵称补配；此前用户确认部分客户照片显示的结果仍保留，本轮未重新核验所有记录。
4. 真实多页列表无重复遗漏，员工/添加方式/群名筛选，跨主体切换、撤权和午夜/跨年范围；指标、排行、明细用真实记录核对。
5. 真实弱网、头像失败恢复及真实数据量：首页<2秒、明细首屏<1.5秒、分页<1秒、图表<2秒；记录事件发生、接收、入库、可见时间验证<1分钟，不能以30秒轮询代替证据。
6. 被踢操作人是否有可靠且获授权来源；没有就确认降级展示“平台未提供”。删除Top5是双向关系流失还是员工主动删除，仍须验收方确认，保持现口径。
