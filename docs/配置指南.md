# 企业微信和钉钉接入配置指南

接口清单、参数用途、代码位置、官方文档来源和当前验证状态见 [企业微信与钉钉接口及配置说明](企业微信与钉钉接口及配置说明.md)。

本实现适用于企业内部自建接入。若公司使用企微第三方服务商应用、钉钉第三方应用或其他授权模式，需要替换对应适配层，不能直接复用内部应用密钥流程。

代码核对日期：2026-10-24，源码基线 `24e6586`。本地启动与 uv 命令见 [README](../README.md)，Linux 源码部署见 [宝塔非容器部署](宝塔非容器部署.md)，容器部署见 [宝塔部署](宝塔部署.md)，日常发布见 [本地一键同步部署](本地一键同步部署.md)。修改配置后，本地或 systemd 服务需重启；Compose 部署需执行对应配置的 `up -d` 重新创建容器，单纯 `restart` 不加载新的容器环境变量。

## 一 向公司申请的资料

请公司提供企业微信管理员和钉钉应用管理员协助，以及经过允许的测试员工、客户和群。开发者不需要索取管理员个人密码；由管理员配置，或授予最小必要的开发管理权限即可。

| 平台 | 需要的信息 | 用途 |
| --- | --- | --- |
| 企业微信 | 每个主体的 CorpID | 标识接入企业 |
| 企业微信 | 客户联系及所需群接口可用的 Secret | 获取接口 access_token；普通应用 Secret 不一定具备所需能力 |
| 企业微信 | 回调 Token、EncodingAESKey | URL 验证、消息验签和解密 |
| 企业微信 | 客户联系使用范围、接口权限、可信 IP 等配置 | 决定可访问员工、客户及群；以当前管理后台要求为准 |
| 钉钉 | CorpID、AppKey/Client ID、AppSecret/Client Secret、AgentID | 企业内部 H5 应用身份和服务端调用 |
| 钉钉 | 应用可见范围、用户信息权限、H5 首页及安全域名等配置 | 使测试用户可以从工作台打开应用并免登 |
| 运维 | 公网 HTTPS 域名、部署主机、证书和出网策略 | 平台回调及工作台访问 |

不要将 Secret、Token、AESKey 发到公开群、代码仓库、截图或 AI 对话中。填写到本机或服务器 `.env`，该文件已在 `.gitignore` 中排除。

## 二 企业微信配置

1. 请管理员登录 [企业微信管理后台](https://work.weixin.qq.com/)，确认测试企业，并获取 CorpID。
2. 在当前企业的客户联系或相应应用配置中，确认应用有本项目所需的客户联系、员工资料、客户群读取权限。具体菜单名称与应用模式相关，由管理员在后台核对。
3. 取得可用 Secret。回调 Token 和 EncodingAESKey 在对应回调配置页生成或按平台要求设置。EncodingAESKey 为平台要求的 43 字符编码值，不是随意的 43 字符密码。
4. 假设在应用中使用凭据引用 `ACME`，设置：

```dotenv
WECOM_ACME_SECRET=由公司提供
WECOM_ACME_TOKEN=与企微回调配置保持一致
WECOM_ACME_AES_KEY=由企微后台生成的EncodingAESKey
```

5. 登录本应用管理页，新增主体：名称、CorpID、凭据引用 `ACME`。复制系统生成的回调 URL。

   凭据引用必须匹配 `^[A-Z][A-Z0-9_]{0,40}$`，如 `ACME` 或 `BETA_2`。运行时 CorpID 来自此处的主体配置；可选 `WECOM_ACME_CORP_ID` 只用于检测脚本。主体可先创建再补齐密钥，页面“凭据就绪”仅表示三项非空，不能代替格式与权限检测。CorpID 创建后不能通过现有页面或更新接口修改，提交前请核对。
6. 将回调 URL、相同 Token 和 AESKey 配置到企业微信，保存时平台会发起 URL 验证。服务必须已部署为平台可访问的 HTTPS 地址，不能直接填 `localhost`。
7. 若平台要求可信 IP，填写服务器实际出口 IP；开放平台回调需要的入口。通过受控测试添加或删除关系，观察管理页任务与业务明细。
8. 对每个企业重复配置，不同企业的密钥不可混用。主体停用后会停止接收其回调与展示数据。

最常见的排查顺序：公网可达 → HTTPS 正常 → CorpID 一致 → Token/AESKey 一致 → Secret 和接口权限 → 可见范围与可信 IP。平台返回的错误码保留在任务错误中，日志不输出带 access_token 的请求 URL。

已有独立构造报文的本地加解密验证，以及后续真实群回调和业务处理记录，见 [真实验收记录](真实钉钉环境验收记录.md)。新主体仍须独立验证回调、资料权限和业务链路，不能复用另一主体的通过结果。

## 三 钉钉配置

1. 请管理员登录 [钉钉开放平台](https://open.dingtalk.com/)，在目标企业创建或授权一个企业内部 H5 微应用。
2. 获取企业 CorpID、应用 AppKey/Client ID、AppSecret/Client Secret 及 AgentID，并设置测试用户可见范围。
3. 按本应用调用需要开通“通过免登码获取用户信息”和“用户详情”等权限；后台具体权限名称和审核要求以当前应用为准。[钉钉免登用户接口](https://open.dingtalk.com/document/development/obtain-the-userid-of-a-user-by-using-the-log-free)
4. 将应用首页指向部署后的 HTTPS 根地址，配置平台要求的域名及安全相关项。
5. 写入服务器配置并重启：

```dotenv
DING_CORP_ID=公司钉钉企业ID
DING_CLIENT_ID=内部应用AppKey
DING_CLIENT_SECRET=内部应用AppSecret
DING_AGENT_ID=内部应用AgentID
PUBLIC_ORIGIN=https://你的应用域名
COOKIE_SECURE=true
```

6. 当前服务端使用内部应用凭据获取应用 accessToken，再通过 H5 免登 code 获取 userid 和用户详情。[钉钉内部应用 accessToken 接口](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app)
7. 先通过 `create-admin` 将公司给出的真实钉钉企业内 userid 初始化为管理员，再由该用户从钉钉工作台进入。系统不会因为拿到了有效钉钉身份就自动赋予业务权限。
8. 管理员在页面新增其他用户、分配主体授权。测试未授权用户、过期免登、退出、撤销授权，以及钉钉 PC、iOS、Android 容器。

CorpID、AppKey、AgentID、UserID 不是同一个字段；不要混填。`DING_AGENT_ID` 作为应用信息保留，当前免登接口调用不使用它。

## 四 群变更必须单独验证

用一个专门测试群验证主动退出和管理员移出，保留脱敏回调样本，核对是否提供退出原因、离群成员标识和操作人。当前实现不会根据群主猜测踢人操作人，也不把群成员差集当成精确事实。

回调只有人数与原因且缺少有效成员证据时，保存为“其他 / 待核实”，不计入外部客户退群或被踢指标。有有效事前/事后快照、人数一致且识别为外部客户时，可归入主动退群或被移出，保留 `resolution=inferred`，不能称为平台逐人确认；内部成员和未知部分单独保留。完整文本回调成员 ID 若与差异冲突，也保留待核实，具体见 [群成员识别规则](群成员识别状态.md)。

新主体上线先执行 `uv run python -m app.cli sync-profiles --tenant-id 实际主体ID`。该命令保存当前员工、客户和群成员资料，并预取成员头像；建群/成员进群回调也会预取。只有先保存可靠的成员与媒体引用，离群后才有可用历史来源。已有缓存客户的真实退群与被移出头像已有通过记录，全新无缓存客户首次下载、员工本人授权头像及被踢操作人来源仍待独立收口。

## 五 诊断与历史头像补全

在项目根目录运行，确保 `.env` 与目标服务使用相同数据库和 `PAYLOAD_KEY`：

```powershell
# 只读本地收件箱、任务与事件，最近 1～100 条；不调用平台或重放回调
uv run python -m scripts.check_callbacks --limit 10
# 仅统计启用主体下非演示历史事件的头像补全目标，不调用平台、不写入
uv run python -m scripts.backfill_avatars
```

平台检测命令及 `--offline`、一次性 code 等参数见 [README](../README.md)。回调检查输出脱敏时间、状态及事件类型，不输出人员标识或原始密文；结果正常不能代替真实客户端显示验收。

在已决定补全历史头像时，执行 `uv run python -m scripts.backfill_avatars --apply`。此操作先生成 SQLite 备份，再按同主体员工/客户 ID 及已有可信成员证据请求资料、下载头像、写入历史媒体引用；它会访问真实平台并修改本地资料与事件，不是只读诊断。不修改事件分类、人数或删除方向，不按同名补图，平台已拒绝且无历史缓存的照片不能保证恢复。数据库备份不替代媒体和密钥的完整备份。

## 六 推荐的交接方式

向管理员提供：应用用途、需要的接口权限、测试人员名单、最终 HTTPS 地址、服务器出口 IP，以及本指南。由管理员完成后台设置，通过公司认可的安全渠道交付密钥。先在测试企业验证，完成联调记录后再决定是否接入生产数据。
